## For agents — Testing

Installed by Surfaceplate. Do not edit this file in an adopting repository.

- A failing test is information, not an obstacle. Never weaken, delete, skip, or rewrite a test to
  obtain a passing result — route a genuinely wrong test as its own change, with a reviewer.
- An unexpected deterministic-output change is an audit trigger. Investigate the cause before
  touching a golden or snapshot fixture; regenerating one to absorb an unexplained delta destroys
  the evidence that something changed.
- Run the cheapest focused check after each substantive edit, then widen. Before handing work back:
  focused tests, contract/schema tests, deterministic/golden tests for material output,
  lint/format/type/build, and dependency checks if dependencies changed.
- Report the exact command quoted, `PASS` / `FAIL - CODE` / `FAIL - ENVIRONMENT/DEPENDENCY` /
  `NOT RUN`, warnings and skips preserved. Never claim a suite passed when you ran a subset.
- New behaviour needs a new test. Add the failing regression test first when fixing a defect. Where
  something genuinely cannot be tested, say so and record it as an evidence gap — never leave it
  silent.
