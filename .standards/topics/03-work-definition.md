# Topic 3 — Work definition

Installed by Surfaceplate. Do not edit this file in an adopting repository.

*What is this task, and where does it end?*

## Every task needs a work packet

Do not begin unbounded work. Before editing, the task must state:

- objective and explicit non-goals;
- bounded files or ownership area;
- requirements and constraints;
- acceptance criteria;
- expected tests and verification commands;
- data, security, and confidentiality constraints;
- accountable task owner, required reviewer, and escalation triggers.

Use `.standards/templates/work-packet.md`. If the repository operates an activity or development
register, the packet must cite a registered activity ID — see Topic 4 (Work tracking).

If the task does not establish these, ask for them. Do not infer scope from adjacent code.

The agent may inspect the repository, choose the implementation mechanism within the contract,
edit code, run checks, and report evidence. The agent must not silently expand scope beyond the
packet, or represent human approval as already given.

## For agents — Work definition

Installed by Surfaceplate. Do not edit this file in an adopting repository.

  non-goals, the bounded files or ownership area, requirements and constraints, acceptance criteria,
  expected tests and verification commands, data/security/confidentiality constraints, and an
