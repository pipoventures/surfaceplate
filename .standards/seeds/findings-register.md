# Findings

The register of known limitations, defects and open questions about this repository.

**This file existing is not the practice.** It was created when Surfaceplate was adopted here, so
that the `assurance_findings` control has a real place to point at. What the control asks is that
limitations are written down rather than smoothed away; a register that stays empty while findings
are known is a finding about this repository, not a satisfied control, and the checker cannot tell
the difference, because it checks that this file exists and holds no placeholder.

## Register

Each entry records at least: a stable identifier; what was found and where; how severe it is and
why; who found it and when; and what closes it, or the decision that it stays open.

| ID | Finding | Severity | Status |
|---|---|---|---|

**No findings are recorded yet.** That is an accurate statement about this repository on the day
this file was created, and it stops being accurate the moment a limitation is known and not here.

## Adding an entry

Record a finding when it is found, in the same change where practical. Severity is a judgement;
state the reasoning so it can be disagreed with. Close an entry by naming what closed it, never by
deleting it.
