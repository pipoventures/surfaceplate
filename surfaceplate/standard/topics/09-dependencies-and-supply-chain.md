# Topic 9 — Dependencies and supply chain

Installed by Surfaceplate. Do not edit this file in an adopting repository.

*What comes in from outside, and on what terms?*

## Dependencies

Use a declared and locked dependency set.

Run the repository's approved dependency review or vulnerability check when lockfiles or direct
dependencies change, and record the command and result in the completion evidence. A package
manifest is not a vulnerability assessment.

Do not add a dependency to solve a problem that the existing toolchain already solves. New direct
dependencies on a calculation or security path are an audit trigger (Topic 6).

## Trust boundaries

Treat these as security-sensitive surfaces requiring explicit review: authentication and
authorisation; data upload and download; export and reporting; database access and query
construction; deserialisation of external input; file path handling; subprocess and shell
invocation; and any code that constructs a request to an external system.

Never weaken an existing credential, authorisation, or permission control to make a task easier.
That is a stop-and-ask, always (Topic 2).

## Human decisions — dependency and security exceptions

Dependency exceptions and security control waivers are human decisions. Record them. An agent may
recommend a treatment; it may not accept a dependency risk or grant a waiver on its own authority.

## For agents — Dependencies and supply chain

Installed by Surfaceplate. Do not edit this file in an adopting repository.

- Use a declared, locked dependency set. Run the approved dependency review or vulnerability check
  on every lockfile or direct-dependency change, and record the command and result. A manifest
  alone is not a vulnerability assessment.
- Do not add a dependency the existing toolchain already solves the problem with. A new direct
  dependency on a calculation or security path is an audit trigger.
- Treat authentication/authorisation, data upload/download, export/reporting, database access,
  deserialisation of external input, file-path handling, subprocess/shell invocation, and requests
  to external systems as security-sensitive surfaces requiring explicit review.
- Never weaken an existing credential, authorisation, or permission control to make a task easier —
  that is always a stop-and-ask.
- Dependency exceptions and security waivers are human decisions — recommend, never grant them
  yourself.
