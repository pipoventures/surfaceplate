## Decision

**Reserve the name now; release later.** The current version is uploaded to PyPI once, by hand,
from `.github/workflows/publish.yml`, so that nobody else takes `surfaceplate` (free on the index
on 2026-09-02, verified: the index answers 404 for it). The package carries the classifier
`Development Status :: 3 - Alpha`, so the index states the status beside the name. **Every live
instruction keeps naming the git form until 1.0**: the PyPI upload is a reservation, not the
install route, and the status line's "not independently audited" is not contradicted by anything
an adopter is told to run.

## Context and alternatives

Not chosen: publishing nothing until the independent audit (leaves the name to whoever takes it
first); publishing now as the install route (puts an unaudited package under a public name as the
thing adopters are told to install, and needs the interim wording replaced everywhere).

## Mechanism

Trusted publishing: PyPI accepts the OIDC identity of the named workflow in the named GitHub
environment, so no API token exists to store, leak or rotate. The workflow runs only on manual
dispatch, refuses unless the maintainer types the version, verifies the manifest, builds, installs
the wheel into a clean environment and runs the tool, then publishes. Two steps are the
maintainer's alone, listed under `H8`.

## Impact

- Numerical/model output: none. Contracts/schemas: none.
- Security: one new workflow with `id-token: write` in one job, scoped to the `pypi` environment;
  no secret. The third-party action is pinned to its release branch, not a commit; pinning it to a
  commit SHA is the stronger form and is left for the release that item 10 authorises.
- Documentation: this record; `H8`; `ACT-058`; the changelog.

## Evidence
