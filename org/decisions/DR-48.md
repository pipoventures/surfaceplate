## Decision

**One rules module, imported by both the checker and the wizard, in the payload.**

1. Create `surfaceplate/rules.py` holding: the `effective_from` rule (a date or instant, not in
   the future); the `review_by` rule (between today and today plus 400 days); the `revisit_by`
   rule (not past); the `application_id` pattern; the placeholder pattern; and "a named path is
   tracked by git", which `SP051` requires and which "exists" does not satisfy.
2. `surfaceplate/check_conformance.py` and `surfaceplate/adopt/validators.py` both import it.
   Neither restates a rule the module holds.
3. The module is added to the install payload in `install_standard.build_payload`, as `DR-20`
   requires for any payload addition, and `tests/check_vendored_current.py` covers it.
4. A parity test asserts that for every `SP` code that reads a profile field, a wizard
   validator refuses the same input, or an exemption names the reason. History-only codes
   (`SP034`, `SP035`) are exempt by name.
5. `validators.check` treats `None` and any non-string as blank.

## Context and alternatives

The review found the wizard accepting a future `effective_from`, a 401-day `review_by`, a past
`review_by`, a one-character `application_id`, basic-ISO dates the schema refuses, and untracked
paths, each of which the checker's first run rejects (`F66`). The rules were duplicated and had
drifted. Alternative considered: keep both copies with a test that they agree (rejected: the
duplication is the defect, and the test would be a third copy).
