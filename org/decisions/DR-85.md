# Decision Record

- Decision ID: DR-85
- Date: 2026-09-11
- Application: Surfaceplate (the framework itself) — a third route through adoption, for people
  the terminal is the obstacle for, and what an AI agent may do on an adopter's behalf.
- Decision owner: Mario Pipo (maintainer), who asked for it and chose all three of its shape
  questions. Drafted by the agent under `ACT-100`; confirmed by merging.
- Status: accepted — implemented by `ACT-100`.
- Risk level: 3 — it adds a public command and, more consequentially, publishes a prompt that
  tells an AI agent what it may do inside an adopter's repository.
- Related work item: `ACT-100`; reads against `DR-35` (the two explanation registers), `DR-40`
  (ask what a human holds), and Topic 2's reservation of decisions to people.

## Decision

**`surfaceplate agent-prompt` prints a prompt to paste into an AI coding assistant. The agent may
run the commands and explain every decision. It may not make one.**

1. **Scope.** The agent may run `install --dry-run`, `install`, `adopt --propose`, `check`, and
   `adopt --answers` once the human has filled the record, and may create scaffolded artefacts the
   human ticks. It **must not** write a value into any `needs-human` line, choose a conformance
   level, decide a gate's status, or write a rationale in the adopter's name.
2. **Tailored, and redacted through `doctor._redact`** — the same single choke point, so there is
   one thing to test and no collector can bypass it. The prompt carries **counts, never file
   contents**.
3. **No recommended level.** `plan.recommended_level()` needs the adopter's own two risk answers,
   and `core/CONFORMANCE_LEVELS.md` is explicit that the level *"is not derived automatically from
   the stack, the repository size, or the data classification"*. The prompt asks the two questions
   and does not answer them.
4. **Authority is the installed documents.** The prompt tells the agent to read
   `.standards/topics/*.md` rather than rely on its training, and quotes Topic 1's rule at it:
   *"Generated or extracted content, and an agent's summary of it, is never authority."*
5. Named `agent-prompt`; `--register simple|advanced` exposes the two registers `DR-35` already
   built, previously reachable only from inside the wizard.
6. **The welcome screen offers both routes** (`ACT-101`, added by the maintainer after seeing the
   first design). `[Enter]` sets up here; `[A]` quits and prints the prompt. A subcommand nobody
   knows exists is barely a feature, and the person this route is for — the one the terminal is an
   obstacle for — is the least likely to find it in `--help`.

   **Printed to the terminal, not shown on a screen.** The prompt exists to be *copied*, and text
   inside a full-screen Textual app is the one thing a reader cannot easily take out of it.
   `doctor --report` makes the same choice for the same reason.

## Context

Adoption had two doors and both assume a terminal. The maintainer asked for a third — *"in case
someone finds the terminal too difficult to complete or have doubts about stuff… that way we can
deliver to knowledgable and also newbies."*

**This is not a new adoption mechanism.** It is `--propose`/`--answers` narrated. `DR-35` already
records why narration is needed: a live adoption hit *"I don't know what this is"* three times in a
row, and `explanations.py` was written in response. The agent is pointed at that material; it is a
third delivery channel for explanations the tool already owns, beside the wizard's help line and
the answers record's `choices:` block.

### Why the contract is the feature

The framework's three most expensive defects of the year — `F40` (a README proposed as a work
register), `F84` (a placeholder-bearing file proposed and then rejected), `F144` (a checkout step
recorded as the implementation of a test control) — were each **the tool supplying a value nobody
chose**. Each produced a repository that passed every check and guarded nothing.

A prompt saying "help me adopt Surfaceplate" invites an agent to do exactly that, in the friendliest
possible wrapper, one level above where the guards are. So the prohibition is stated as rules with
their reason attached, and the prompt closes by telling the agent that refusing *"just pick
something sensible"* is the most useful thing it can do.

### Rejected: the agent drafts answers for approval

Offered to the maintainer and declined for this round, correctly. It is the most useful shape and
the one that needs work first: **the provenance sidecar has no origin for an AI-drafted value.**
Topic 10 forbids an AI-proposed value silently becoming a recorded fact, and an agent-drafted
answer accepted by a human would today be recorded as `typed` — which is false. Doing it honestly
needs an `ai_drafted` origin, a schema change, and a check that no draft reaches a written profile
unconfirmed. That is its own activity, and the right one if this command sees real use.

## Impact

- `surfaceplate/assist.py` — new, tool-side. **Not vendored and cannot be**: it reads
  `surfaceplate.adopt`, and `adopt/plan.py` imports `surfaceplate.rules` absolutely, so the wizard
  package has no flat form. It therefore carries plain absolute imports and no flat fallback,
  unlike `check_conformance.py`, which needs one because it runs from `.standards/`.
- `cli.py` — one entry in `_COMMANDS`, one two-line handler, following `_cmd_doctor`.
- `scripts/front_door.sh` — the command runs there, piped through `grep -q "MUST NOT"`, so a
  prompt that renders empty or loses its contract fails the front door rather than an adopter.
- `README.md`, `INSTALL.md`, `SUPPORT.md` — the third route named where each audience looks.

## Evidence

- **`tests/check_code_registers.py::agent_prompt_names_commands_that_exist`** — every
  `surfaceplate …` invocation in the generated prompt is parsed out and checked against the real
  CLI, commands and long flags alike. **This is the load-bearing one**: the prompt is prose whose
  entire purpose is to be followed, so `S3` applies to it more sharply than to any other output
  here. Verified by effect: renaming `--propose` to `--propoze` in the prompt fails the suite and
  names the flag.
- **`tests/test_install_and_check.py`** — twelve checks, run through the real command as a
  subprocess rather than by import, so the CLI wiring is exercised too: the repository path, home
  directory and username are each absent from the output; the contract's rules are present; no
  form of level recommendation appears; and it renders correctly for a repository that has never
  adopted **and** for one that has.
- `scripts/front_door.sh` on a clean machine, via `.github/workflows/front-door.yml`.
- Read by eye on `B-no-deps` and `A-stranger` — the two ends of the range it serves.

## Limitations

**Nothing here makes an agent obey the contract.** The prompt is text; a model may ignore it. This
framework's own position is that detection beats prevention, and what the design can do is refuse
to make disobedience easy: the agent is told to read the installed documents rather than
paraphrase, and `adopt --answers` refuses a record with `needs-human` lines outstanding, so nothing
can be *skipped*.

**But it can be answered by the wrong party, and the record will not say so.** The provenance
sidecar cannot distinguish "the human typed it" from "an agent typed it on their behalf" — both are
`typed`. That is the honest gap, it is the same gap the rejected option would have had to close,
and it is stated in `INSTALL.md` where an adopter will meet it rather than only here.

**The prompt also crosses a data boundary the tool cannot police.** Pasting it sends its content to
whichever provider the adopter's assistant uses. The redaction is real and the contents of no file
appear, but Topic 8 makes provider approval a human decision, and this command cannot make it. The
prompt says so in its own closing section.
