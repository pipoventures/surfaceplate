## Decision

1. **An explicit "create it" choice (`F87`).** Where a gate's artefact can be created from a seed
   and the seed's path is free, the artefact dropdown's first row reads "create it from the
   framework's seed: <path>". Choosing it is recorded as scaffolded, exactly as leaving the
   field blank was; the offer screen confirms before anything is written; the help says what
   the seed contains. A blank no longer carries a hidden meaning. The same row appears for a
   control whose implementation reference has a seed.
2. **Every artefact offered, matches first (`F88`).** A control's implementation reference for a
   pattern-A control other than the lock file offers every artefact discovery found, ranked with
   the name matches first, as the gates do, instead of only the name matches. Discovery offers
   every tracked Markdown or YAML file of the adopter's own, ranked by directory, rather than
   only those under a fixed list of directories; the per-field cap after ranking stands.
3. **A seed for the findings register (`F88`).** `assurance_findings` gains a seed at
   `docs/FINDINGS.md`, a true and complete file holding no findings, offered through item 1.
4. **`adopt --edit` (`F86`).** `surfaceplate adopt --edit <profile path> <value> [--because
   <reason>]` rewrites that one line of the profile through the same renderer and verification
   as the wizard, and records it in the provenance sidecar as typed with a timestamp and the
   reason. A path the profile does not have is refused with the nearest paths named. The
   checker is unchanged; a hand edit made without the flag is still a hand edit.

## Context and alternatives

`F87`, `F88` and `F86` are the maintainer's own from two runs of the rebuilt wizard: *"it forces
me to select one file in my repo. What if I have none?"*, *"what if I don't have any? Also, if I
have one there is no dropdown list"*, and the hand edits he made to Plutos's profile the same
afternoon. Alternatives put and not chosen: keeping the blank and explaining it; widening the
offer without a seed; a seed without widening; a checker warning when the profile is newer than
its record, alone or as well; leaving edits as a known limitation.

## Impact

- Numerical/model output: none. Contracts/schemas: none.
- Command line: one new flag on `adopt`; the exit-code contract (`DR-49`) is unchanged.
- Security/data: `--edit` writes only the two files the wizard writes, atomically.
- Reproducibility/lineage: the sidecar gains typed entries with a timestamp and reason.
- Operations/release: the seed is a new file in the payload's `seeds/`, which is not vendored.

## Evidence

- `ACT-052`, each item test-first.

## Limitations and follow-up

`--edit` takes one scalar line at a time; a list-valued line is addressed by index. Editing a
value the review marks as not editable (the level, the interface answer, a gate's status) is
refused, because it changes which other lines exist.
