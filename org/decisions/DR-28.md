# Decision Record

- Decision ID: DR-28
- Date: 2026-08-31
- Application: Surfaceplate (the framework itself) — the result of exercising it against another
  repository, and the corrections that result required.
- Decision owner: Mario Pipo (maintainer), per the decision-maker convention recorded in
  `org/decisions/README.md`.
- Status: accepted — implemented in the same change.
- Risk level: 2 — it changes what the profile scan accepts in every adopting repository, and it
  records the first evidence this framework has about a repository other than itself.
- Related work item: `ACT-016`. Closes `F25` and `F26`.

## Decision

**The framework was exercised against Plyego and passed. Two defects it exposed are fixed here.
Plyego is not adopted, and nothing was written to it.**

1. `placeholder_scan_exemptions[*].rationale` is excluded from the profile placeholder scan, and
   nothing else is (`F25`).
2. `SP032`'s placeholder remedy is rewritten to be true of every gate and to name the exemption
   route (`F26`).
3. **Plyego's adoption is a separate decision**, deferred until the per-gate cost is put in front of
   the maintainer. This record contains observations about Plyego and no changes to it.

## Context and alternatives

### What the gate was for, and what it returned

`org/RELEASE_PLAN.md` item 5 has said from the beginning that no real adopter existed, and `DR-7`
records that every adopter previously named in this repository was **fabricated**. The whole
verification sequence — `DR-25` through `DR-27`, five packets — was built so that this moment would
mean something.

The result, against a throwaway clone of a 3,049-file repository with Python, TypeScript, a user
interface, 1,092 markdown files and its own `ACT-nnn` governance:

```
Advisory (2) - not a failure:
  - activity/register.md is exempt from the placeholder scan by declaration: ...
  - dependency_lock: verified against uv.lock

PASS - all conformance checks satisfied.
```

At `essential`. Checks that did real work without being tuned for it: `SP046`/`SP047` located
Plyego's actual blocking `gitleaks` step and confirmed its exit code is not discarded; `SP051`
verified `uv.lock`; `SP030` refused `standard` on six gates; `SP052` caught `documentation_authority`
declared without the gate that verifies it.

### The two defects, and why neither was reachable from here

Both appeared within an hour of the framework meeting a repository it did not write. Neither is
exotic.

**`F25`** is the sharper one. An exemption's rationale must say why an artefact legitimately carries
a placeholder token, which means quoting it — and `SP020` scanned every string in the profile, so
declaring the exemption failed the profile. **The remedy for the defect could not be used without
causing it.**

It was invisible from inside because surfaceplate's own two exemptions *describe* the tokens without
reproducing them, a habit formed by `F14` and `F15`. The trap needed an adopter who wrote the
natural sentence — which is the first thing a real adopter does.

**`F26`** is smaller and more embarrassing: `SP032`'s remedy read *"A template is not a design
policy"* for all nineteen gates, and named no remedy at all. The exemption mechanism has existed
since `DR-22` and the finding that most needs it never mentioned it.

### Why the exclusion is one field

The fix could have been a general exemption mechanism for the profile, mirroring the artefact one.
Rejected: `SP020` exists to catch *"the profile was installed, not adopted"* — unfilled slots in
`application_id`, `owner`, dates. A general escape hatch would let an adopter suppress exactly that.

`placeholder_scan_exemptions[*].rationale` is the one field in the profile whose **purpose** is to
discuss these tokens. Everything else stays scanned, including the `artefact` path beside it and
every other rationale — a gate's, a deferral's, a control decision's. Three negative controls hold
that line, and they matter more than the positive case: an exclusion that swallowed the whole
profile would pass the positive case identically.

### What the gate found about Plyego, recorded as observation only

These are findings **about Plyego**, and Plyego's own register is where they belong. They are
recorded here because they are the evidence for what adoption would cost, and because omitting them
would make this record a success story rather than a result.

| Observation | Detail |
|---|---|
| No CI step runs the tests | 547 test files; four workflows, checking generated doc blocks, the activity register and secrets. Nothing runs the suite, so `deterministic_tests` and `contract_tests` are unsatisfiable. |
| `standard` is out of reach today | Six gates must be `required` and have no artefact: `authority_map`, `change_record_before_completion`, and the four interface gates — Plyego ships a UI, so those are live rather than `not_applicable`. |
| No `CHANGELOG.md` at the repository root | |
| No documentation authority map | 1,092 markdown files with no stated precedence — the defect this framework names most often, at a scale this repository has never tested. |
| 15 of 19 gates would start deferred | Each needs an owner and a `revisit_by` that `SP054` now enforces. |

**The interface gates ran for the first time.** Surfaceplate sets `builds_user_interface: false`, so
four of the nineteen gates had never been exercised against a repository that answers `true`. They
behaved correctly, and that is not something this repository could ever have established about
itself.

### Why Plyego is not adopted here

Decided this session. Adoption means writing a profile and a set of governance artefacts into
another repository, and every gate decision — required, deferred, with what owner and what date — is
a statement about how Plyego actually works. Those are the maintainer's to make with the per-gate
cost in front of them, not an agent's to infer from a probe.

`org/decisions/README.md` and the working method are explicit that an agent may inspect, plan and
report, and may not accept risk or conclude a validation on someone's behalf. A profile is precisely
such a statement.

### Alternatives rejected

- **Adopt Plyego first and fix afterwards.** Rejected by the maintainer, consistent with the
  standing instruction from earlier in this project: *"fix the instrument first."* It would also
  have committed the evasive wording into Plyego's profile permanently.
- **Reword rather than fix.** The `PASS` obtained before the fix used a rationale worded to avoid
  the token. `DR-22` already names that workaround as bad, in its own words.
- **Widen `PLACEHOLDER_PATTERN` or make it case-sensitive** so that lowercase `tbd` inside quotes
  does not match. Rejected for the reason `DR-17` gives: every tightening of the token vocabulary
  trades one class of false positive for a class of false negative, and `F16` records that the
  mention-versus-use problem is not fixable by any vocabulary. The declaration route is the answer,
  which is why making it usable was the fix.

## Impact

- **Numerical/model output:** none.
- **Contracts/schemas:** none. `placeholder_scan_exemptions` is unchanged; only what the checker
  scans changed.
- **Security/data:** none. Nothing was written to Plyego, and the probe ran in a scratch clone whose
  git objects were shared read-only.
- **Operations/release:** an adopter can now declare an exemption in the sentence they would
  naturally write. `SP032`'s output changes for every adopter.
- **`org/RELEASE_PLAN.md` is corrected rather than annotated.** Item 5 and limitation 3 both stated
  that no adopter had been exercised. That is now false in part, and leaving it standing under a
  later correction would return the old claim to any partial read.

## Evidence

- **The probe, re-run against the fixed checker with the rationale an adopter would actually
  write** — quoting the token rather than avoiding it. `PASS`. The earlier `PASS` is *not* this
  packet's evidence: it was obtained with wording chosen to dodge the defect being fixed, so citing
  it would be validating the wrong artefact.
- Five permanent probes, of which **three are negative controls**: the scan still fires on a
  top-level field, on a string inside a gate, and on a deferral's rationale.
- `SP032`'s output asserted to name `placeholder_scan_exemptions` and to no longer say "design
  policy".
- `test_install_and_check.py` moves 149 → 154.
- A correction to this session's own reporting, recorded because it nearly produced a false finding:
  the first measurement of Plyego's placeholder hits used a **looser regex than the checker's**,
  omitting the `\b` anchors, and reported four false matches in `docs/governance/control_framework.md`.
  Re-measured with `PLACEHOLDER_PATTERN` itself, that file has exactly one hit and it is a **genuine
  unfilled slot** — *"a trusted technical contact (TBD)"*. The instrument under test must be the
  instrument used to test it.

## Limitations and follow-up

- **One repository is not a sample.** Plyego is the maintainer's own project, sharing conventions
  and an author with this one. It is a far better test than self-conformance and it is not an
  independent one.
- **`essential` is the only level demonstrated.** `standard` was refused, correctly, and `full` was
  never approached — so the four record-based controls of `DR-26` and `DR-27` remain proven by
  fixture alone.
- **The history audit was not exercised in anger.** Every gate was dated to the adoption date, which
  is what a real adopter does, so no historical commit was judged. What the audit does against six
  years of real history is still unknown.
- **Plyego's own findings are recorded here and nowhere else.** They belong in Plyego's register,
  and putting them there is part of an adoption that has not happened.
- **A rationale reading only `TODO` now passes**, per `F25`.
