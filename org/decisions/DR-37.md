- Decision owner: Mario Pipo (maintainer), per the decision-maker convention recorded in

- Status: accepted — implemented in the same change (`ACT-028`).

- Related work item: `ACT-028`. Closes `F37`.

## Decision

**Rendering is asserted as named properties over the compositor's own output, not captured as a
snapshot — and every such assertion must be seen to fail before it is trusted.**

`F37` records what prompted this: `ACT-027` shipped 87 green checks and a visibly broken interface,
because every one of those checks asserted structure and none asserted what reached the terminal.
The fix for the six defects is ordinary work. The decision worth recording is what replaces the
missing check.

1. **Read the rendered lines.** `tests/test_render.py` uses
   `[strip.text for strip in screen._compositor.render_strips()]` — the same path
   `App.export_screenshot` walks before turning the result into SVG. Textual publishes no plain-text
   export, so this reaches for a private attribute knowingly.
2. **Assert properties, not a snapshot.** Each check states a property in words — "every legend
   renders the keys it names", "a label and its value share a line", "at least three gates are
   visible at 80×24" — and fails for one readable reason.
3. **Calibrate every assertion by watching it fail.** All eleven failed against the unfixed code;
   three were then re-broken deliberately after the fix and each caught its own defect again.

## Context and alternatives

### Why not a snapshot

A full-screen golden would have caught all six defects, and it is the obvious tool. It was rejected
on this project's own stated grounds: `.claude/rules/surfaceplate-tests.md` treats golden and
reference outputs as an **audit trigger**, and warns that *"regenerating a golden file to absorb an
unexplained delta destroys the only evidence that something changed"*.

A snapshot of this particular thing would churn constantly — the wizard's copy is still being tuned,
and Phase 1's whole contribution was rewriting the explanation text for 31 catalogue items. Every
wording change would redden the suite for a reason unrelated to correctness, and the only sustainable
response to that is to regenerate, which is the habit the rule exists to prevent. A property survives
a copy edit and fails only when the property genuinely stops holding.

The honest cost: properties catch what they were written to catch and nothing else. A snapshot would
have caught the unindented wrap and the noisy detected-signals line too, and neither of those is in
`tests/render`'s assertions — both were found by a human reading the output, which is the practice
this record is really establishing. Properties are the regression net; looking is still the discovery
method, and `F37` exists because looking was skipped.

### Why the private attribute is acceptable

`screen._compositor` is not public API. The alternatives were: assert nothing about rendering
(the status quo that produced `F37`), add `pytest-textual-snapshot` (a new dev dependency, and the
snapshot approach rejected above), or parse the SVG export back into text (the same private path,
with a lossy round-trip in the middle). Reaching for one private attribute, in one helper, with a
comment saying so, is the smallest of those. If a future Textual moves it, the suite fails loudly on
import rather than silently passing — which is the property that matters.

### What this does not fix

Verification catches regressions in what it was told to watch. It does not substitute for looking at
the thing, and the two faults found *after* the suite went green — the level list wrapping to column
0, the detected-signals line listing four full paths — prove that: both passed every property and
were obvious on sight. The practice this record commits to is therefore both: assert the properties,
**and** read the rendered output before claiming anything about it.

## Impact

- **Numerical/model output:** none.
- **Contracts/schemas:** none. No change to `plan.py`, `sections.py`, `interview.py`, `wizard.py`,
  `render.py` or any content module, so all 87 pre-existing checks remain valid unchanged.
- **Security/dependencies:** none. No new dependency.
- **Operations/release:** the interface an adopter meets is materially different — legends that show
  their keys, a label column, one help line at a time, and a gate catalogue that shows several gates
  and shortens as it is answered.

## Evidence

- `tests/test_render.py`, 11 checks, all failing against the unfixed code — one per defect, with the
  resume screen missing both of its only keys.
- Three seen-to-fail controls after the fix: restoring `placeholder=spec.label` re-fails the
  duplicate-label check; sending one legend back through markup re-fails the key check; disabling
  gate collapse re-fails the density check at 80×24, reporting "only 1 gate(s) on screen".
- Rendered output read directly for all three frames, which is how the two further faults above were
  found.
- All nine suites pass: contracts 167, installer 179, adopt 59, provenance 5, adopt-tui 23, render
  11, identifiers 135, registers 10 (37 F codes), vendored 57 files.

## Limitations and follow-up

- **A property suite is a floor, not a substitute for looking.** Stated above, and demonstrated in
  the same packet.
- **`screen._compositor` is private.** Named as a knowing choice rather than discovered later.
- **No real unscripted session has been driven by a human on the fixed build.** The maintainer's own
  run is what found `F37`, and it is what will judge whether this is now usable.
