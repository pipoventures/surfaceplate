## Decision

**Two channels, one rule.** External signal reaches this repository two ways, and both are already
established practice here rather than new invention — this record makes the pattern explicit so it
is applied consistently rather than reinvented per occurrence:

1. **An adopter's report** (`surfaceplate doctor --report`, `SUPPORT.md`, the issue forms) becomes an
   `F<n>` in `org/FINDINGS.md`, carrying a provenance preamble naming the report as its source — the
   same treatment `F101`–`F111` already give the second cross-provider review. **It is verified
   against the code before it is recorded, never accepted on the reporter's authority alone**, and
   the finding body separates the reporter's claim from this repository's assessment.
2. **An independent review** (`H4`, `H6`; the packet built at `ACT-060`, `DR-64`) returns as a named
   assurance-evidence record (`AE-0002`, `AE-0003`) and, for Part B, findings recorded the same way.

**No automated signal may populate `independent_validator`.** A PEP 740 attestation, an OpenSSF
Scorecard result, a Best Practices badge, download counts, or GitHub traffic data are useful,
genuinely third-party-held evidence — but none of them is a named person exercising judgement, and
`DR-64` already defines what closes `F6` as exactly that. Recording any of them as an independent
validation would be the precise fabrication this framework exists to prevent. Where such a signal is
cited at all, it is labelled as automated, third-party-held supporting evidence, distinct from
independent validation, in the same document that cites it.

## Context and alternatives

Not chosen: treating an adopter's bug report as self-evidently true and acting on it directly
(rejected — an external report can itself be mistaken about this repository's actual behaviour, and
skipping verification would let a false report change the record); waiting for a formal audit before
recording anything from ordinary adopter feedback (rejected — the whole reason `F119` exists is that
no such feedback had anywhere to land; five observed installs, per `H15` below, will surface more
usability defects than a year of a formal process).

the Part-A channels, and (separately, and never on an agent's authority) deciding whether a returned
review names an `independent_validator`.
