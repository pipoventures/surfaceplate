## Decision

**A structural question is answered by picking from what is actually in the repository. Prose stays
typed. And prose may span lines, because it always could in the format — only this renderer could
not place it.**

1. **Discovery first.** `discover.py` scans the target repository once, git-tracked only, and every
   structural field is offered the real candidates: files for a precondition artefact, directories
   for a record register, lock files for `dependency_lock`, top-level source directories as
   pathspecs, and **the actual step names out of the workflow YAML** for a pattern-B control.
2. **Selection over free text, but only where a candidate list is honest.** A `Select` where the
   value must match something real, a `SelectionList` for `enforcement` (a fixed schema enum that
   should never have been a comma-separated string), and inline suggestions on a field where a
   candidate helps but must not constrain — a pathspec is a pattern, not a path. Rationale and
   description fields stay free text with their editable worked example: a judgement cannot be
   picked from a menu, and pretending otherwise would invite accepting a canned reason nobody means.
3. **Multi-line prose is written as a literal block scalar.** `|-`, not `>-`, because a literal
   round-trips byte-for-byte and `wizard._verify` compares the reparse against what was assembled.

## Context and alternatives

### Why this reconciles `example_answers.py` rather than reversing it

That module deliberately refused to offer example artefact paths, and said why: *"a plausible-
looking example risks being copied unedited."* It was right, and the rule underneath it is the one
`discover.py` keeps — **never offer something that isn't there**. An invented path that looks real
is worse than a blank field; a file that exists in the adopter's own repository is a different kind
of thing entirely. The distinction is enforced, not asserted: `tests/test_discover.py`'s load-bearing
half checks that a gitignored file, an untracked file and an ignored directory are never offered,
and that every offered path exists on disk.

Where git cannot answer, the functions return nothing and every field degrades to the plain text box
it was before. An empty dropdown that cannot be answered would be worse than the problem.

### What the provenance guarantee required

`tests/test_provenance.py` proves no string reaches a written profile that no answer supplied, by
feeding sentinels to every free-text field and allow-listing what the tool legitimately contributes.
Discovery threatened that directly: the allow-list is built from every field's `choices`, and a
`select` field's choices are read from the repository — so the first run after this change admitted
twenty-two CI step names and a pile of file paths into it.

**An allow-list that grows with the adopter's repository is not an allow-list.** It is narrowed to
closed enums (`choice`, `multiselect`) only; `select` fields are answered with sentinels exactly
like free-text ones, because their values are chosen by a human and must be traceable as such. It
carries 53 entries and is repo-independent again.

### The blocker, fixed rather than forbidden

Validating newlines away at the field would have been smaller and would have told an adopter that a
paragraph is not allowed in a paragraph field. The format has never had that restriction. PyYAML
builds the scalar — including `|2-` where a first line begins with a space, and a quoted fallback
where trailing whitespace means a literal block could not round-trip — and this renderer's only job
is to re-indent the continuation lines to wherever the key sits.

### Alternatives rejected

- **Pickers everywhere, rationale included.** Rejected by the maintainer: it risks people accepting
  a canned rationale they do not mean, which is what the binding rule and the provenance walk exist
  to prevent.
- **Only fields where a wrong format fails a check.** Rejected as too narrow — it would have left
  gated paths as free text, where a typo silently produces a gate that guards nothing.
- **A screen-level `priority=True` arrow binding.** Simpler, and wrong: a priority binding fires
  before the focused widget, so it would steal the arrows from the option list, the radio set and
  the text area, where they legitimately move a cursor. The single-line text box — the one widget
  with no use for them — hands them back instead.

## Impact

- **Numerical/model output:** none.
- **Contracts/schemas:** none. The written profile's shape is unchanged; multi-line prose is new
  content in an existing field type, which the schema has always permitted.
- **Security/dependencies:** none. `discover.py` reads and never writes, and shells out only to
  `git ls-files`.
- **Operations/release:** an adopter is now offered their own repository's files and CI steps rather
  than a blank box, and a paragraph in a rationale writes correctly. `cli.py` gains a guard so no
  renderer error can reach anyone as a traceback.

## Evidence

- Ten suites pass: contracts 167, installer 179, adopt 64, provenance 5, adopt-tui 29, render 16,
  **discover 14 (new)**, identifiers 137, registers 10 (38 F codes), vendored 57 files.
- Discovery run against the real Plutos repository: 40 artefacts, 10 register directories,
  `requirements.txt`, real pathspecs, and 20 real CI step names — the last being the field the
  maintainer could not answer at all.
- Seen-to-fail controls: making the frame non-scrolling again re-fails the cramped-window check;
  removing the block scalar re-fails the readable-output check while the round-trip half correctly
  still passes, since a quoted scalar round-trips too.
- **Two assertions in this packet were found to be too weak and were tightened**, which then
  exposed three further defects (the always-ticked checkbox, the focus-stripped underline, the
  wrong `Select` sentinel). Recorded in `F38` because it is the clearest demonstration yet of
  `DR-37`'s point that a property test nobody has calibrated proves nothing.
- Rendered output read back frame by frame before anything was published.

## Limitations and follow-up

- **Candidate lists are capped at 40 and ranked by heuristic.** The cap is on the offer, never on
  the answer; every field that takes a list also accepts a value not in it. A repository whose
  governance documents live somewhere unusual will rank them below `docs/`, which is a guess this
  record owns rather than hides.
- **`discover.py` does not check that a candidate is *suitable*,** only that it exists and is
  tracked. Whether `docs/README.md` is a sensible precondition for a gate remains the adopter's
  judgement, and the checker's own rules still apply afterwards.
- **No unscripted human session has been run on this build.** Every one so far has found something
  no test did.
