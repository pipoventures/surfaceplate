# Decision Record

- Decision ID: DR-42
- Date: 2026-09-01
- Application: Surfaceplate (the framework itself) — what `surfaceplate adopt`'s screens may assert.
- Decision owner: Mario Pipo (maintainer), per the decision-maker convention recorded in
  `org/decisions/README.md`.
- Status: accepted — implemented in the same change (`ACT-034`).
- Risk level: 3 — it changes what every adopter reads on every screen, and it fixes an unbounded
  redraw loop this project shipped one packet earlier.
- Related work item: `ACT-034`. Closes `F42`, `F43`, `F44`, `F45`, `F46`.

## Decision

**A display may not assert more than its evidence supports, and that rule binds the interface
exactly as it binds the profile.**

1. Text that is shortened says so, and says it **in the text** rather than in a layout rule.
2. A completion counter counts completion, not the presence of a value the tool itself supplied.
3. A candidate list states whether anything actually matched.
4. A progress counter is derived from the thing it describes.
5. A screen redraws to reach a state, and then stops.

## Context and alternatives

### What the audit was, and why it found things nine suites did not

The maintainer stopped a real Plutos run part-way and asked for every path to be walked,
screenshotted and audited against this project's own standard. Sixteen screens were rendered at
**80×24** — the size the interface is designed for, and the size no previous packet had actually
looked at, having read most screens at 100 or 120 columns where the defects hide.

`ACT-032` worked where it had been measured: on the real Plutos repository `work_registration`
proposed `activity/register.md` and `decision_before_implementation` proposed the real decision log.
What the audit found was a different class of defect entirely, and one this project is
badly placed to excuse.

### The through-line, which is the reason these are one packet

`org/RELEASE_PLAN.md` binds the wizard's *data* path: *it asks, the human answers, the tool writes*.
`tests/test_provenance.py` enforces it, and `F40` was the last breach of it. Every finding here is
the same defect in the **presentation** path:

| Finding | What the display claimed | What it had |
|---|---|---|
| `F42` | this is the whole explanation | ~a third of it |
| `F43` | this section is answered | a status the level fixed |
| `F44` | one of these twelve is the answer | twelve files that matched nothing |
| `F45` | you are at step 7 of 7 | one of ten sections, numbered twice |

A framework whose central claim is that a control must mean what it says cannot ship an interface
that rounds its own certainty up. `ACT-032` fixed this in the data layer and left it standing in the
presentation layer, which is the honest summary of why this packet exists.

### `F46` is a regression this project shipped, and the tests that missed it are the finding

`ACT-032` started the level screen's caret on the recommended level. `_move_caret` redrew the
prompts with `clear_options()`, which resets the highlight and posts an event that arrives back in
`_move_caret`. At index 0 that settled, because the reset landed on the value it already had; from
any other index the events alternate forever — **4,484 redraws for one paint**, on every repository
whose answers recommend `standard` or `full`.

Three things about it are worth carrying forward.

- **`ACT-032`'s tests passed against it.** They asserted `OptionList.highlighted == 2` after one
  `pause()`, and it *is* 2 on half the iterations. Reading state cannot detect a loop; the
  regression test counts `_move_caret` calls instead.
- **The existing guard could not have worked.** `_move_caret` already returned early when the
  incoming index matched the previous one; because the events alternate, it never matched.
- **Two attempts to fix the symptom failed before the cause was found.** The visible fault was a
  meta line naming the wrong level; setting the highlight earlier, then making the meta
  deterministic, both left it wrong. The working method's loop-breaker names this exactly — a second
  failed patch means the approach is wrong, not the implementation — and tracing the calls found a
  loop rather than a stale value.

### Why the ellipsis moved out of CSS

`.gate-desc` declared `text-overflow: ellipsis` and it never rendered once. A truncation rule that
can silently fail to mark its own truncation is not a mechanism this repository should rely on for
honesty, whatever the reason for the failure. The budget now applies to the string in
`_first_sentence`, so the `…` is part of the value and survives whatever the layout does to it.

### Alternatives rejected

- **Let gate explanations wrap in full.** Honest and unbounded: nineteen gates × four lines at 80
  columns is a wall, and the maintainer's standing complaint is length. The 150-character budget with
  a visible `…` keeps the catalogue navigable while the full text stays in the focused-field help.
- **Hide the unmatched candidates.** `DR-38` is explicit that discovery orders and never filters, and
  an adopter whose register has an unexpected name would then have no way to pick it. Saying nothing
  matched costs one line and removes the false implication.
- **Guard `_move_caret` harder.** Tried, and it is the wrong shape of fix: the problem was not the
  last value written, it was that writing produced another write.
- **Shorten the 19-gate catalogue at `full`.** Out of scope by design. `DR-40` keeps every gate
  visible because `standard` and above require each to be *declared*; shortening it changes the
  standard, not the wizard.

## Impact

- **Numerical/model output:** none.
- **Contracts/schemas:** none. The written profile is unchanged in shape and content.
- **Security/dependencies:** none.
- **Operations/release:** every adopter gets a level screen that stops redrawing, explanations that
  say when they were shortened, a counter that counts what they supplied, and four fewer questions
  on the defaults route.

## Evidence

- Nine suites pass: contracts 167, installer 183, adopt 82, provenance 6, adopt-tui 41, render 18,
  discover 18, identifiers 183, registers 10 (46 F codes).
- **The provenance allow-list did not grow.** `ACT-034` makes the tool propose more values, and the
  packet's own condition was that every one trace to a shipped field default or an answer already
  given. `PROVENANCE=PASS (6 checks)`, unchanged.
- **Every finding seen to fail first**, each re-broken deliberately afterwards:
  - `F42` — *"184 chars of explanation, neither complete nor elided"*;
  - `F43` — *"hint claimed completion with nothing supplied: '1 of 1 answered …'"*;
  - `F45` — *"no step label for: ['route']"* and *"shared by more than one section: ['7 of 7 — ']"*;
  - `F46` — *"`_move_caret` ran 4484 times for one paint: [0, 2, 0, 2, …]"*.
- The defaults route's remaining questions drop from 14 to 10 on a repository with no user
  interface, and the four removed are the ones whose value the wizard already held.
- All sixteen screens re-rendered at 80×24 and read after the change.

## Limitations and follow-up

- **The audit was at two widths, 80 and ~200.** Nothing was checked between them, and `F42` was
  width-dependent, so that class of defect is bounded rather than eliminated.
- **The defaults screen is still 46 proposals in one flat list**, in raw dotted ids, with the origin
  repeated per row. Measured during this audit and **not fixed**: it is a presentation improvement
  with no honesty defect behind it, and this packet was scoped to the claims the interface makes.
- **The label column still truncates option text at 80 columns** — `Set defaults - propose answers
  f…`. It elides visibly, so it is not dishonest, but the two most consequential options in the
  wizard cannot be read in full. Recorded, not fixed.
- **`ACT-033` is still the gap.** A repository with nothing in it is now told plainly that nothing
  matches — which is honest, and still leaves it unable to pass.
- **The defaults route has still never been driven to completion by a human.**
