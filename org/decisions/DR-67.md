# Decision Record

- Decision ID: DR-67
- Date: 2026-09-08
- Application: Surfaceplate (the framework itself) — what an adopting repository receives, and
  which agent's file the instructions name as the authority map.
- Decision owner: Mario Pipo (maintainer). Drafted by the agent under the approved `ACT-066`
  packet; confirmed by merging, per the convention `DR-64` records.
- Status: accepted — implemented by `ACT-066`.
- Risk level: 2 — it changes what every adopting repository receives and adds a public installer
  flag. Not level 3: the default is unchanged, nothing is removed from an existing install, and no
  control's meaning moves.
- Related work item: `ACT-066`; findings `F122`, `F123`. Extends `DR-30` (one body, several
  emitters) without amending it.

## Decision

**Every agent channel is selectable, all of them are on by default, and declining one is
recorded and reported.**

1. `surfaceplate install --agents claude,copilot` narrows the per-agent destinations to the
   channels named. Omitting the flag installs every channel, so **no existing adopter's install
   changes**, and naming every channel is identical to naming none.
2. The channel table lives in `rules.py` — the module the checker and the wizard already share
   (`DR-48`) — because the checker needs the same set and cannot import the installer, being
   vendored standalone beside it.
3. **`AGENTS.md` is written either way.** It is agent-neutral; the vendor-specific file is
   `.github/copilot-instructions.md`.
4. A narrowed install records `agents` in `INSTALL.json`, and `check_conformance.py` reports the
   declined channels on **every** run, in the shape of `DR-29`'s declined-hook note.
5. The checker does not demand a file it was told not to write: `SP006`/`SP007` are not raised for
   a declined channel.
6. **`F123`:** `authority.md` no longer names one vendor's file as the place an authority hierarchy
   must be stated. It names *the repository's own agent instruction file*, and says what that
   means.

## Context and alternatives

**The finding asked for something narrower, and this deliberately does not do it.** `F122`'s
proposed remedy was *"make the Copilot channel opt-in at install"*. Building that literally would
make one vendor's channel opt-in while the other stayed default — **the same neutrality breach one
layer along**, and in a framework whose `DR-30` exists precisely to stop it privileging the agent
its author happens to use. It would also have been a breaking change for every existing adopter,
where this is not. The divergence from the finding's stated remedy is recorded here rather than
made silently.

**Rejected: detect which agents a repository uses and install accordingly.** It reads well and it
breaks the wizard's binding rule — *it asks, the human answers, the tool writes*. A repository with
no `.claude/` directory today may acquire one tomorrow, and an installer that inferred the answer
would have written a decision nobody made.

**Rejected: filter at each emission site.** A filter that must be remembered at each of six loops
is a filter that will be forgotten at the seventh — which is `F58` exactly: `DR-30`'s per-agent
pattern was applied to the six instruction documents and not to the seven skills, and nothing
noticed for five releases. The filter is applied once, over the assembled payload.

## Impact

- Contracts/schemas: none. `INSTALL.json` gains an optional key; absent means every channel, so
  records written before `0.17.0` read correctly with no migration.
- Security/data: none.
- Operations: `.github/copilot-instructions.md` is no longer created in a repository that declined
  Copilot. That file is created by the **conformance-block upsert**, not by the payload — see the
  limitation below, which is the half this decision nearly missed.
- Documentation: `INSTALL.md`, `README.md`, and `authority.md`'s authority-map paragraph.

## Evidence

`tests/test_install_and_check.py`,
`test_an_agent_channel_can_be_declined_and_the_declining_is_never_silent` — every case run in
**both directions**, because a change justified by neutrality that was only tested one way would
prove nothing. Asserted: neither channel's artefacts appear when the other is chosen;
`.github/copilot-instructions.md` specifically is absent; `AGENTS.md` is present either way; the
choice is recorded; the file count differs by exactly the declined channel's payload size, with
both the baseline and the per-channel size **derived** rather than written down; the check reports
the declined channel and does not raise `SP006`/`SP007` for it; a default install still writes
both and records no narrowing; an unknown channel and an empty list are refused.
`INSTALL_CONFORMANCE=PASS (288 checks)`.

The positive control matters as much as the negatives: without *"a default install still writes
both channels"*, every other assertion would pass against an installer that had simply stopped
writing agent files at all.

## Limitations and follow-up

**Two mechanisms write into an adopting repository, and checking one is not checking what an
adopter receives.** The payload writes `.github/instructions/` and `.github/skills/`; the
conformance-block upsert **creates** `.github/copilot-instructions.md` outside the payload
entirely. `F122` was first recorded here claiming the installer does not write that file, on the
strength of a comment in `install_standard.py` that is true of the payload and not of the
installer. That entry is corrected in place. Filtering the payload alone would have left the one
Copilot artefact an adopter most notices, and the test asserts its absence by name for that reason.

Only two channels exist. A third agent is a new entry in `rules.AGENT_CHANNELS` and its emitter,
not a change to this decision.
