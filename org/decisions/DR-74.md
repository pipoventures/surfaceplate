## Decision

**A check may not report a negative it was not in a position to establish.** Three defects and one
rule.

1. **`F133` — a copy is not a rename.** `historical_paths` rejects `--follow`'s `C` records
   outright, and additionally drops any candidate former name that **still exists in the tree
   today**: a rename leaves the old path gone; a copy leaves both.
2. **`F134` — a replay is a pure function of its record.** `wizard.run` takes `use_draft`, and
   the `--answers` path passes `False`. No draft is read, and none is written, whatever happens.
3. **`F135` — one module owns "is this file a lock".** `rules.LOCK_FILES` is the single list, and
   `pyproject.toml` is not in it. It remains typeable; it is never proposed.
4. **The rule, applied where it was already broken.** `doctor._git_config` returns
   `set` / `unset` / `unknown`, and an unanswerable question is reported as unanswerable — never as
   `unset`, never as `ok`.

## Context and alternatives

All three findings came from `audit/PATHWAY_SWEEP_REPORT_2026-09-09.md` and were reproduced here
before being acted on. Three routes were costed:

- **(A) Narrow fixes, ship, triage after.** Fastest. It would have shipped 1.0 on fifteen
  unreproduced reports, two of which (`PW-09`, the exception template that fails its own schema;
  `PW-13`, no removal procedure exists) are adoption-facing.
- **(B) Adjudicate everything, then fix, then ship.** Complete, and the objection is shape rather
  than cost: it spends the same care on empty directories left behind (`PW-15`) as on a control
  passing while not holding.
- **(C) Fix the class.** Chosen.

**Why the class is a real class and not a rhetorical one.** `F133` and `PW-04` are one defect in two
places. The audit reported *"the artefact was present"* having found a **seed** under an alias.
`doctor` reported *"`core.hooksPath` is unset"* having found **no git to ask**. Both assert an
absence from an observation that could not have found the thing — the rule this framework states in
its own instructions and broke in its own code. `_git_config`'s docstring said *"or `None` when
unset **or** git cannot answer"*: the conflation was written down and passed over.

**The template already existed.** `rules.dependency_manifest` returns `found` / `none` / `unknown`
and never waives on `unknown` — written the day before under `DR-73`, and got wrong first time in
exactly this way, by treating "git answered, nothing found" and "git could not answer" as one state.

**Scope was checked before it was chosen, not after.** 22 sites can turn a git failure into an
answer; several already return an error string beside the empty result. The pass was bounded, and if
it had not been this record would say so instead.

## The three fixes, and why each is the shape it is

**`F133`.** The narrow fix — refuse `.standards/`-owned paths — is correct as far as it goes and
addresses only the seed. The rule chosen states what a former name *is*, so it holds for a
byte-identical file anywhere. It errs toward **reporting**: if a path is renamed away and something
unrelated later takes its old name, that name stops being trusted and the strict pre-`F30` behaviour
returns for it. A false violation can be cleared by a person; a violation never reported cannot.
`F30`'s remedy survives — verified on a genuine rename, and on this repository's own two-rename
`test_convention` chain.

**`F134`.** Not "clear the draft afterwards" but "never involve it". A draft exists to protect a
human mid-interview from losing an hour of answers; a replay has nothing to protect, because its
answers are already in a file the adopter wrote and still holds. The same reasoning that keeps
`sections.build_profile` pure.

**`F135`.** Not "ban `pyproject.toml`". **This repository names it, and is right to**: its
dependencies are pinned exactly there and it has no separate lock. A name cannot distinguish a
`pyproject.toml` that pins from one that declares ranges, and a tool that cannot distinguish them
must ask rather than assert. So it is offered and never proposed, and a repository in that position
is asked instead of told.

## Evidence

- **`F133`, both directions.** The scaffold reproduced from a clean start: `git log --follow`
  reports `C100 .standards/seeds/activity-register.md activity/register.md`, and before the fix
  `historical_paths` returned both names while `blob_exists` was `False` for the artefact and `True`
  for the seed. After: `['activity/register.md']`. A genuine `git mv` still yields
  `['activity/register.md', 'docs/OLD.md']`, and this repository's own `test_convention` precondition
  still resolves through two renames.
- **`F134`.** The sweep's sequence re-run here: a refused replay now leaves **no draft**, so its own
  *"Nothing was written"* is true, and the next replay's error moves on to a different field rather
  than repeating the previous attempt's.
- **`F135`.** `pyproject.toml` is out of `rules.LOCK_FILES`; a repository whose only pins are in its
  manifest now offers **no** lock candidate, so the field is asked. The manifest question still
  answers `found`, so `DR-73` does not waive the floor for it.
- **`PW-04`.** With `PATH=/nonexistent`, `doctor` reports every scope as *"could not be
  established … this is not the same as unset"*, and the checker does not print a clean bill.
- `tests/test_install_and_check.py` 316 checks, `tests/test_adopt.py` 276, `tests/test_discover.py`
  65 — each of the three carries a regression test that names its finding.

## Limitations and follow-up

**The class pass covered the sites the sweep reached, not all 22.** `PW-04` was the instance with
evidence; the remainder were read and left where they already distinguish the states. A later pass
should assert the property mechanically for every site rather than for the two tested here — the
test added now proves the property for the checker and for `doctor`, and does not prove it for, say,
`is_tracked` under a broken repository.

**`F135` leaves `SP051` unchanged, deliberately.** It still accepts any tracked, non-empty,
placeholder-free file as a lock, so naming a Markdown page still passes. `DR-25` records that
boundary as permanent: this framework checks that a named artefact exists, never that its contents
are honest. What is fixed is the tool *proposing* the wrong file as a discovered fact; what an
adopter deliberately declares remains theirs.

**`requirements.txt` stays classified as a lock**, and is genuinely ambiguous — often a pinned set,
often a range list. It is left as a lock because that is the conventional use and because the
alternative, asking every Python repository, is worse for the common case.
