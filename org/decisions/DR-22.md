## Decision

**An artefact may be declared exempt from the placeholder scan, in the profile, with a rationale.**

`placeholder_scan_exemptions` is a new optional top-level array in the application profile. Each
entry names an artefact and states why it legitimately contains placeholder tokens. `SP050` fires
when an exemption names an artefact that does not exist.

Three properties make this an exemption rather than a hole, and each is tested:

1. **It is narrow.** It suppresses the token branch of `SP032` and nothing else. An exempt artefact
   must still exist and must still be non-empty; both remain checked.
2. **It is declared in the profile, not in the artefact.** A template able to exempt itself would be
   exactly the condition `SP032` exists to catch.
3. **It announces itself.** Every exemption is reported as an advisory on every run. A control that
   has been narrowed says so.

## Context and alternatives

### The finding

`PLACEHOLDER_PATTERN` is matched against whole file text, so a document that **mentions** a token is
indistinguishable from one that **contains** an unfilled slot. `F16` was found the only way such a
thing can be: the `CHANGELOG.md` entry documenting the placeholder control failed the placeholder
control, because it named the tokens it was describing.

`DR-17` had already removed a shape-based branch for a related reason — it could not separate
notation from a slot — and recorded that the remaining token branch has the same defect **narrowed,
not eliminated**: four fixed strings instead of any angle-bracketed string, but the same inability
to tell mention from use. `F16` was recorded as *"not fixable by any token vocabulary"*, and that
remains true. What is fixable is the question of who decides.

### Why this shape, and not the obvious alternatives

- **A marker inside the artefact** (`<!-- placeholder-scan: skip -->`). Rejected, and this is the
  decisive one: the artefacts most likely to be blank forms are templates, and a template carrying
  its own exemption marker would pass `SP032` while being exactly the blank form the control exists
  to reject. Self-exemption inverts the control.
- **Excluding whole file types**, such as never scanning `CHANGELOG.md`. Rejected: it would exempt
  every adopter's changelog including ones that really are unfinished, and it hard-codes one
  repository's problem into everyone's rules.
- **Ignoring tokens inside code spans or fenced blocks.** Rejected on measurement, not taste:
  `F16`'s own instance had the tokens in ordinary prose, so this would not have fixed the case that
  raised the finding. It also reintroduces the format-guessing `DR-17` removed.
- **Leaving it open.** Considered seriously, and it was the recorded position until now. What
  changed is the demonstration that the same pattern works: `F17` — the identifier check reading
  every GitHub URL as a claim about this organisation — was closed by a **declared exemption** in
  `ORGANISATION.md`, with the declaration derived rather than restated. That is the precedent this
  follows.

### The precedent, and where this deliberately differs from it

`ORGANISATION.md`'s quoted-evidence block pairs an exemption to **both** a path and a token, so that
a *different* wrong spelling in the same file is still caught. That pairing is right there and wrong
here.

There, the exempted thing is one specific wrong value, and other wrong values in the same file are
still defects. Here, the four tokens are a closed set and an artefact that legitimately discusses
placeholder detection will discuss all of them. Pairing per token would mean four entries per
artefact, each of which must be maintained as the prose changes — maintenance cost with no
detection benefit. The exemption is therefore per-artefact, and the narrowness comes from *what* is
suppressed (the token branch only) rather than from *which tokens*.

### What this costs, stated plainly

**An adopter can exempt an artefact that really is unfinished.** Nothing prevents it. The
protections are that the declaration sits in the profile where a reviewer reads it, that a rationale
is mandatory and *"it keeps failing"* is visibly not one, and that the exemption is reported on every
run rather than taking effect silently.

That is weaker than a check and it is not presented as equivalent to one. `core/CONTROL_PRINCIPLES.md`
principle 9 already places the quality of a human declaration outside what this framework may claim
to verify; this is another instance of that boundary, made visible rather than hidden.

## Impact

- **Numerical/model output:** none.
- **Contracts/schemas:** additive and backward-compatible. `placeholder_scan_exemptions` is optional;
  an existing profile validates unchanged.
- **Security/data:** none.
- **Operations/release:** an adopter whose governed artefact documents this control can now declare
  it rather than being forced to avoid naming the tokens — which was the previous workaround, and a
  bad one: a changelog that cannot describe a control is a worse artefact than one needing an
  exemption.
- **Surfaceplate uses it on itself.** `CHANGELOG.md` is a precondition artefact for two gates and
  documents the placeholder control. It is declared exempt, with the rationale, and the advisory
  appears on every run of this repository's own check.

## Evidence

Four cases, and note that **three of them test what the exemption does *not* suppress**:

| Probe | Result |
|---|---|
| Token in a gated artefact, no exemption | `SP032` fires |
| Same, with the exemption declared | Suppressed, **and** the run reports the narrowing |
| Exempt artefact emptied | `SP032` still fires — exemption does not reach the empty check |
| Exemption naming a missing artefact | `SP050` fires |

`test_install_and_check.py` moves 111 → 115. The stale-exemption case matters because an exemption
that outlives the artefact it was written for silently widens what the check tolerates — the same
reasoning `ORGANISATION.md` gives for refusing to start when a quoted-evidence path is missing.

## Limitations and follow-up

- **`F16`'s underlying defect is not gone.** Whole-file matching still cannot separate mention from
  use. What changed is that a human can now say which artefacts legitimately mention the tokens,
  visibly. The finding is closed on that basis, not on the defect being solved.
- **No owner or revisit date is required**, unlike a deferral. A changelog that documents this
  control will always contain the tokens, so an expiry would be ceremony that expires into noise.
  If exemptions are ever observed accumulating without cause, that judgement should be revisited.
- **Nothing checks that a rationale is a real one.** Only that it exists and is non-empty.
