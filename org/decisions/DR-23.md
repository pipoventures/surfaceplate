# Decision Record

- Decision ID: DR-23
- Date: 2026-08-31
- Application: Surfaceplate (the framework itself) — a decision about how it is published.
- Decision owner: Mario Pipo (maintainer), per the decision-maker convention recorded in
  `org/decisions/README.md`.
- Status: accepted — implementation is partly the maintainer's, and is listed below.
- Risk level: 2 — it changes where the project lives and what is publicly visible. Publication is
  not reversible in practice.
- Related work item: `ACT-007`. Unblocks `F8`.

## Decision

**Publish surfaceplate as a new public repository containing no prior git history. Keep the
existing repository private, renamed and archived, with its true history intact.**

Four parts:

1. A new **public** `pipoventures/surfaceplate`, whose first commit is the current tree.
2. This repository renamed to **`surfaceplate-history`**, made archived and read-only. Nothing is
   deleted and no history is rewritten.
3. Development **moves** to the public repository. This matters: `F8`'s remedy is a branch ruleset,
   and a ruleset must guard the repository where work actually happens, not an archive.
4. A branch ruleset on the public repository requiring **all four** status checks and a pull
   request before merge.

## Context and alternatives

### What publication is for

One thing, concretely: `F8`. The conformance check runs in a workflow file that lives inside the
repository it checks, so deleting the file removes the check. The remedy is a **branch ruleset** —
a rule held in GitHub's settings rather than in the repository, so deleting the workflow makes the
merge impossible instead of making the check disappear.

That was unavailable. Verified 2026-08-31, both endpoints:

```
GET /repos/pipoventures/surfaceplate/rulesets            -> 403
GET /repos/.../branches/main/protection                  -> 403
"Upgrade to GitHub Pro or make this repository public to enable this feature."
```

So: pay, or publish. Paying was ruled out by the maintainer. `DR-12` already commits this project
to being git-native, free and public, so publication is the stated direction rather than a
concession.

### Why not simply make this repository public

The former organisation's name appears in **47 of 51 commits**. Not as stray mentions — until the
`0.12.0` rename the schema namespace was built on it, in the form
`urn:[organisation]:uk:risk-ai:software-delivery-standards:…`, so it is embedded in every schema
`$id`, in `NAMESPACE.md`, `README.md`, `INSTALL.md`, the `org/` documents and the tests, throughout
history.

*This record describes the token rather than reproducing it.* Writing it out here would put it back
on the public surface the whole decision exists to keep clear — and would fail
`tests/check_identifiers.py`, which is how the first draft of this paragraph was caught. That is the
fourth instance of the self-quotation shape this register has recorded — a document describing a
defect reproducing it — and the first three are why the check that caught it exists.

The maintainer holds a standing policy: no reference to that organisation on any brand-facing or
public-adjacent surface, unconditional, with no exception process. Public git history is a
public-adjacent surface.

**The current working tree is clean**, and was already clean but for one changelog line, corrected
in this change.

### Why not rewrite history and then publish

This was the maintainer's first choice, and preparation produced three reasons to reject it. The
third is decisive.

1. **It destroys release verifiability permanently.** Four tags record digests: `v0.11.0`,
   `v0.12.0`, `v0.14.0`, `v0.15.0`. A rewrite changes the trees those digests describe, so every one
   becomes false — and they cannot be recomputed, because archive digests are not reproducible by
   design (`DR-14`: the zip embeds mtimes). The only options would be to delete the digest lines or
   leave them asserting values corresponding to nothing.
2. **It invalidates the citation repair a second time.** Commit `46547ba` — *"Repair citations
   invalidated by the authorship rewrite"* — exists because the first history rewrite broke SHA
   citations. Doing it again breaks them again.
3. **It does not achieve the goal.** After scrubbing, the namespace reads
   `urn:REDACTED:uk:risk-ai:software-delivery-standards`, and internal identifiers of the form
   `[organisation]-uk-it-asr` become `REDACTED-uk-it-asr`. The shape is the identifying part, not
   the single word. So the full cost would be paid for a history that is visibly redacted and still
   suggestive.

And a fourth, which is about what this project is: it would mean **publishing a doctored record** —
commits whose content never existed — from a repository whose entire claim is that it records what
actually happened, including its own mistakes. That trade is not worth making for a word.

### What the fresh repository actually loses

Less than it first appears, and the difference is worth stating precisely because it decided this.

What survives is the **documentary** lineage: 17 changelog releases back to `0.2.0`, 23 decision
records, 17 coded findings. Those *are* the record. Git history is corroboration of it.

What is absent is commit-level corroboration, and **16 commit SHAs** cited across the records will
not resolve in the public repository. That is covered by one plain sentence saying so — an honest
gap, rather than a falsified alternative.

### Alternatives rejected

- **Pay for GitHub Pro, stay private.** Ruled out by the maintainer.
- **Publish as-is with the historical trace.** Would require consciously carving an exception to a
  policy set as unconditional with no exception process.
- **Two live repositories.** Rejected: contradictory authority over the same content is the
  governance defect this framework most often names. The private one is archived, not merely quiet.

## Impact

- **Numerical/model output:** none.
- **Contracts/schemas:** none.
- **Security/data:** the current tree becomes world-readable. Checked before deciding: commit
  author and committer emails across all history are `mario@pipoventures.com` and
  `noreply@github.com` only; no personal filesystem paths; no credentials found by the checks
  available; the `SECURITY.md` response expectation is *best-effort, no guaranteed response time*,
  which survives publication honestly. A full-history secret sweep is a maintainer action listed
  below, and `workflow_dispatch` was added to the scan workflow in this change so that it can be
  run at all.
- **Operations:** `F8` becomes closable once the ruleset exists. It is **not** closed by this
  record — a decision to enable a control is not the control.
- **Visibility of weaknesses.** `org/FINDINGS.md` describes this project's defects in detail and
  becomes public. That is deliberate and consistent with what the framework asks of adopters; it is
  also, accurately, a map. It is recorded as an accepted consequence rather than an oversight.

## Limitations and follow-up

- **This record decides; it does not execute.** Creating the public repository, renaming and
  archiving this one, and configuring the ruleset are the maintainer's actions. Nothing here should
  be read as them having happened.
- **`F8` stays open until the ruleset exists and is shown to block a merge.** Enabling a control and
  demonstrating it are different, and this project has repeatedly found the gap between them.
- **Publication is not reversible.** Making a repository private again does not retract what was
  cloned, forked, or indexed.
- **The archived repository still contains the historical namespace.** It remains private. If it is
  ever made public, this decision must be revisited, not assumed to carry over.
