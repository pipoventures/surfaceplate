# Decision Record

- Decision ID: DR-44
- Date: 2026-09-01
- Application: Surfaceplate (the framework itself) — what `effective_from` means, and the gaps left
  open by `ACT-033` and `ACT-034`.
- Decision owner: Mario Pipo (maintainer), per the decision-maker convention recorded in
  `org/decisions/README.md`. **The remedy was chosen by him, not proposed and adopted:** all three
  candidates change what `SP033`/`SP035` mean, and an agent may not decide a control's semantics.
- Status: accepted — implemented in the same change (`ACT-035`).
- Risk level: 4 — it widens a published schema field and changes what a published control examines,
  in every adopting repository.
- Related work item: `ACT-035`. Closes `F47` and `F48`.

## Decision

**A gate binds from an instant, and the instant is stated rather than inferred.**

1. `effective_from` accepts a full ISO instant as well as a date. Every existing profile stays
   valid and means exactly what it always meant.
2. **A date-only value resolves to explicit midnight** before it reaches `git log`. It never did
   before, and that is `F48`.
3. The wizard records the moment of adoption for a gate whose artefact it creates.
4. `SP033` still refuses a genuinely future instant: widening the field did not widen what it
   tolerates.

## Context and alternatives

### `F48` is the finding, and it inverted the premise of the packet

`F47` was written on the assumption that a date-only `effective_from` meant midnight, so a
repository adopted at 16:37 had that morning's commits inside the audit window. **That assumption
was wrong**, and calibrating the fix is what exposed it.

`commits_touching` passes `--since={date}` to `git log`, and git parses it with **approxidate**,
which fills a missing time from the **current clock**. Measured on git 2.43.0, four commits on one
day, checked at 22:3x:

```
--since=2026-09-01           -> 1 commit
--since=2026-09-01T00:00:00  -> 4 commits
--since=2026-09-01T20:00:00  -> 1 commit     # identical to the bare date
```

So `effective_from` has never meant *"from that date"*, which is what the schema says. It meant
*"from that date at whatever time you happen to run the check"*. The audit window slid forward all
day: **a violation visible at 09:00 was gone by 23:00**, and the later the check ran the less
history it examined. Against this repository's own adoption-day fixture the bare form saw **0 of 4**
same-day commits.

That is `SP035` failing **silently permissive** — the worst direction for a gate, because nothing
reports and the control looks like it is working.

### Why both halves are needed

They are not alternatives; each is useless without the other.

- **Midnight alone** makes the audit deterministic and honest, and it makes `F47` real for the first
  time: with a true midnight boundary, a repository adopted midway through a day genuinely does have
  that morning's commits in scope, and can do nothing about them.
- **An instant alone** would let adoption bind from the right moment while leaving every other
  repository's window sliding with the clock.

Together: the window is a fixed instant, and adoption can name the instant it actually happened.

### Why not the two alternatives that were offered

- **File a gate exception at adoption.** Uses a mechanism that already exists and changes no
  control — but it puts an exception record in every adopter's repository on day one, and `DR-22`
  warns that a growing pile of these is evidence a gate is wrongly scoped. It also treats a
  measurement error as a thing to be excused.
- **Leave it open and warn.** Honest, and it would have left `F48` undiscovered, because `F48` was
  found by *calibrating the fix* rather than by reasoning about the problem.

### What else this packet closed

Everything `ACT-033` and `ACT-034` recorded as deferred, except `F6`, which needs a party outside
this repository and is item 10's business:

- **The resume defect had no regression test**, which was named as a hole in `ACT-033` before this
  packet started. Writing it found that **the fix did not work**: moving the offer before the review
  was necessary and not sufficient, because the condition still asked whether the artefact *answer*
  was blank, and on resume it is not — it holds the path from the cancelled run. The condition now
  asks about the *file*. Seen to fail against both the original defect and the incomplete fix.
- **The review screen now names the files it is about to create.** The scaffold offer's docstring
  said the review "commits", and the review showed only the profile — so the last thing an adopter
  saw before `Ctrl+S` wrote files into their repository never mentioned them.
- **The route options are readable at 80 columns.** Both previously ended in an ellipsis
  (`Set defaults - propose answers f…`), so the choice that decides how the whole rest of the run
  behaves was offered in words the adopter could not finish reading.
- **The defaults screen is grouped by section** with the origin as a tag rather than a sentence
  repeated on every row — about 100 rows instead of 140 at 80×24. A screen approved by pressing
  `Ctrl+S` rather than by reading defeats the only thing that screen is for.

## Impact

- **Numerical/model output:** none.
- **Contracts/schemas:** `effective_from` widens from `format: date` to a pattern admitting a date
  or an instant. Strictly additive; every existing profile validates unchanged. The pattern replaces
  `format` deliberately — `format` is only asserted when a validator attaches a format checker, so
  an `anyOf` over two formats would silently stop rejecting anything for a consumer that does not.
- **Security/dependencies:** none.
- **Operations/release:** **every adopting repository's history audit changes.** The window widens
  to real midnight, so a repository may see a violation it was not being shown. That is the point,
  and it is the direction that surfaces rather than hides.

## Evidence

- Eleven suites pass: contracts 172, installer 186, adopt 82, provenance 6, adopt-tui 43, render 19,
  discover 18, scaffold 21, identifiers 187, registers 10 (48 F codes), vendored 57.
- **`F48` seen to fail**: reverting the midnight normalisation reports
  *"only 0 of 4 same-day commits were in scope"*.
- **`F47` seen to fail**: a date-only `effective_from` on an adoption-day fixture reports `SP035`;
  the instant form does not. The first version of this assertion passed either way — because the
  bare date was excluding the morning anyway — and only became a real test once `F48` was fixed.
- **The resume defect seen to fail twice**: against the original ordering, and against the
  incomplete first fix.
- The schema's positive and negative cases both asserted: date, `hh:mm`, and two offset forms
  validate; `27-08-2026` and `2026-09-01T16` do not.

## Limitations and follow-up

- **The pattern checks shape, not calendar validity.** `2026-13-45T25:99` matches the regex; the
  checker's `datetime.fromisoformat` rejects it and reports `SP033`. The two together are the
  guarantee, and the schema says so rather than implying the pattern is one.
- **This changes what every adopter's audit examines**, and no adopter has yet run it. A repository
  that was quietly passing may now report a violation that was always true.
- **`SP034` compares instants**, so a same-day forward move is caught. This gap did not pre-exist
  the packet — it was **created by widening the field**, since a date-only column made a within-day
  move impossible. Documenting it would have been recording a hole this change had just cut, so it
  was closed instead. A naive value is ordered as UTC, which is a choice about ordering within one
  repository's history and not a claim about which instant it denotes.
- **Only the route screen's options are asserted readable at 80 columns.** A blanket rule would
  force every explanatory label in the wizard to be short whether or not that helped.
- **`F6` remains open** and is item 10's business, not this packet's.
