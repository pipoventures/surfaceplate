# Decision Record

- Decision ID: DR-45
- Date: 2026-09-01
- Application: Surfaceplate (the framework itself) — the install payload, and what `SP049`
  establishes.
- Decision owner: Mario Pipo (maintainer), per the decision-maker convention recorded in
  `org/decisions/README.md`.
- Status: accepted — implemented in the same change (`ACT-036`).
- Risk level: 3 — it adds a file to what every adopter receives, and it narrows the scope of an
  existing check.
- Related work item: `ACT-036`. Narrows `F6`; does **not** close it. Records what is verifiable for
  `ACT-007`.

## Decision

**Ship `MANIFEST.sha256` into the payload, and make `SP049` recompute the framework digest from it
rather than compare two values the installer wrote.**

1. `.standards/MANIFEST.sha256` joins the payload under `DR-20`'s membership principle.
2. `SP049` reports when the installed manifest does not hash to the recorded anchor.
3. `check_vendored_current` **delegates** that file to `SP049` instead of comparing it to source.
4. **`F6` stays open**, and every wording in this change says so.

## Context and alternatives

### What was actually wrong, in `F6`'s own words

> *"`MANIFEST.sha256` is not part of the install payload, so an adopter cannot recompute the anchor
> from their own repository — only compare against what the installer wrote for them."*

`DR-14` gave distribution identity an externally recomputable anchor. It was not recomputable from
inside an adopting repository, because the thing to recompute from was not there. Both values in
`SP049`'s comparison — the profile's declaration and the install record — were written by the same
installer run, so their agreement established that nothing had been edited afterwards, and nothing
else.

### Why the membership principle admits it

`DR-20`: *"A file belongs in the payload when an adopting repository cannot correctly apply,
**verify**, or understand the version it pinned without it."* Verification of the pinned version is
precisely what was impossible without it. `DR-20` also requires that adding a file be a recorded
decision rather than an edit to `build_payload`; this record is that.

### What it does not give, measured rather than assumed

**An adopter still cannot verify their installed files against it.** The manifest covers the release
tree's own paths — `surfaceplate-<version>/...`, 167 entries over `surfaceplate/`, `org/`, `tests/`,
`audit/`, `governance/`, `.github/`, `scripts/` — while the install record covers 57 installed
paths, and several payload files are *transformed* on the way in (the agent instructions get
per-emitter front matter). The two sets are not comparable, and shipping the manifest with the
implication that they were would be worse than not shipping it.

What it enables is one thing, and it is the thing that matters: an adopter can recompute
`sha256(.standards/MANIFEST.sha256)`, confirm it is the anchor their install record claims, and then
compare that manifest against the **published** one — the only value in the arrangement that comes
from outside the repository being checked.

### Why `check_vendored_current` skips it, and why that is not weakening a gate

That check asks *"is the vendored copy current with source?"*. For the manifest, in **this**
repository, the question is not answerable: building the manifest is what happens *after* an
install, so the installed copy necessarily lags the source by one build. It is the same
self-reference `adoption.framework_digest` has always carried, now visible on a second file. An
adopting repository never sees it; only the repository that installs into itself does.

The file is **not** left unchecked. `SP049` now asks the question that actually applies to it —
*does it hash to the anchor recorded for it?* — on every run, in every adopting repository, which is
stronger than a text comparison because it is the check that catches the file being edited. This is
a division of labour between two controls, and the skip names the control that owns it rather than
declaring an exemption.

**Recorded plainly because the rule is strict:** this narrows an existing check's scope, and
`.claude/rules/surfaceplate-tests.md` forbids doing that without recorded human approval. The
approval is the merge of this change, on the convention this register already uses.

### `F6` is not closed, and the wording was written to prevent it reading as though it were

`F6`'s remaining distance is unchanged. The manifest is a file inside the repository being checked;
a party with write access edits it, the install record and the profile together, and all three
agree. The finding's own paragraph on this — *"the problem is not which values are compared but that
one party controls all of them"* — is as true after this change as before.

Two remedies re-examined on the day the repository became public, and still rejected:

- **Signing.** `F6` says it is *"worth doing once there is a public repository"*, which is now true,
  and that it *"establishes provenance, not honesty"* because the key holder is the party with
  commit access. Worth doing on its own merits; recorded here as **not** part of this change and
  **not** closure.
- **The maintainer recomputing and attesting.** `F6` names the closing party as *"someone who is not
  the maintainer"*. Self-attestation is the fabricated-validation failure this framework exists to
  find in others.

### `ACT-007`, and the limit of what an agent can verify

Three of its four done-clauses verify mechanically and are recorded in the register: `F13`/`F15`/
`F16` closed, `DR-22`/`DR-23` recorded, and publication executed exactly as `DR-23` specified — a
new public repository whose first commit is the current tree, with `surfaceplate-history` private
and archived.

The fourth — *"no reference to the former organisation"* — is verified for the forms `DR-23` says
the token took: `tests/check_identifiers.py` Rule 2 asserts every URN authority equals the declared
one, which is where `DR-23` says it was embedded (*"every schema `$id`"*), with Rules 1 and 3
covering the GitHub organisation and stem-sharing tokens.

**A bare prose mention is not covered, and cannot be by an agent working from this repository**,
because `DR-23` deliberately does not write the token down. That is the design working: the record
describes the token rather than reproducing it, precisely so it does not return to a public surface.
The residue is the maintainer's to check, and it is the only thing between `ACT-007` and `done`.

## Impact

- **Numerical/model output:** none.
- **Contracts/schemas:** none. One file added to the payload; no schema changes.
- **Security/dependencies:** the anchor becomes recomputable inside an adopting repository. This is
  a narrowing of `F6`, not a security guarantee, and `SP049`'s own remedy text says so at the point
  of use.
- **Operations/release:** every adopter receives one additional file (~19 KB) on upgrade.

## Evidence

- Eleven suites pass: contracts 173, installer 190, adopt 82, provenance 6, adopt-tui 43, render 19,
  discover 18, scaffold 21, identifiers 189, registers 10 (48 F codes), vendored 57 + 1 delegated.
- **Seen to fail:** appending a line to `.standards/MANIFEST.sha256` makes the checker report
  *"The installed manifest does not hash to the digest recorded for it"* with both digests named.
- Recomputation confirmed against this repository's own install: the shipped manifest hashes to the
  value `INSTALL.json` records.
- The manifest's coverage measured rather than assumed — 167 release-tree paths against 57 installed
  paths — which is why no claim is made that an adopter can verify installed files with it.

## Limitations and follow-up

- **`F6` remains open** and closes only on items 9 and 10.
- **The installed manifest cannot verify installed files.** Stated above; a manifest over the
  *installed* layout would be a different artefact and a different decision.
- **`check_vendored_current` no longer compares one file.** Named, delegated, and recorded rather
  than exempted — but it is a narrowing, and a future reader should see it as one.
- **Signing is not done.** Now worth doing on its own merits; deliberately not folded in here, where
  it would sit next to `F6` and invite being read as closing it.
- **`ACT-007`'s prose clause is unverified** by anything in this repository.
