# Decision Record

- Decision ID: DR-30
- Date: 2026-09-01
- Application: Surfaceplate (the framework itself) — a decision about how its agent instructions are
  delivered, and the first time it is subject to them.
- Decision owner: Mario Pipo (maintainer), per the decision-maker convention recorded in
  `org/decisions/README.md`.
- Status: accepted — implemented in the same change.
- Risk level: 2 — it changes what every adopting repository receives, and it edits a published
  instruction set's delivery for every agent.
- Related work item: `ACT-018`. Closes `F29`. Advances `RELEASE_PLAN` item 3. Corrects `DR-12`.

## Decision

**One canonical instruction body, several emitters, each writing into the file its agent actually
reads.**

| Destination | Front-matter | Reader |
|---|---|---|
| `.github/instructions/<name>.instructions.md` | `applyTo:` | GitHub Copilot — byte-identical to before |
| `.claude/rules/surfaceplate-<name>.md` | `paths:` | Claude Code — new |
| `.standards/agent-instructions/<name>.md` | `scope:` | canonical copy, for any agent not emitted for |
| `AGENTS.md` | marker block | agents reading `AGENTS.md`; created if absent, adopter's content preserved |

**And surfaceplate gains a `CLAUDE.md` importing `@AGENTS.md`**, so the framework is finally governed
by the instructions it publishes.

## Context and alternatives

### The finding

Surfaceplate shipped 501 lines of agent instruction in **GitHub Copilot's format only**. Claude Code
loads managed policy, `~/.claude/CLAUDE.md`, `./CLAUDE.md` or `./.claude/CLAUDE.md`,
`./CLAUDE.local.md` and `.claude/rules/*.md`; `.github/instructions/` is on no list, and
`.github/copilot-instructions.md` is read only by `/init` as a one-time generation step.

Surfaceplate has no `CLAUDE.md`, so **its own instructions reached nothing at all in the repository
that publishes them.** Every packet of governance work here was done by an agent that had never read
a line of them. `F29`.

Established twice over, because inferring behaviour from a filename is the error that caused it: by
direct observation across a working session, with `~/.claude/CLAUDE.md` loading as the positive
control; and against the published documentation, which is exhaustive about the locations.

### `DR-12` was right about neutrality and wrong about mechanism

`DR-12:28` committed to *"Agent-neutral: `AGENTS.md` as the canonical emitted instruction file, with
per-agent emitters"*, and `DR-12:200` records it as *"Decided, not implemented."*

The documentation says plainly: *"Claude Code reads `CLAUDE.md`, not `AGENTS.md`."* So the planned
remedy would have been **equally inert** for the agent in use. The error survived precisely because
the commitment was never built — an unimplemented decision cannot be falsified by contact with
reality.

`AGENTS.md` is still emitted here, because agents that do read it exist and it is the neutral name
the ecosystem has settled on. It is no longer relied on as *the* answer.

### Why `.claude/rules/` and not `CLAUDE.md`

`CLAUDE.md` is the file Claude Code loads, so writing it looks like the direct route. Rejected:
**the adopter owns that file.** Plyego's is 293 lines of repo-specific convention, and a framework
that overwrites it destroys exactly the knowledge no framework can supply.

`.claude/rules/*.md` is the better fit on three counts, and none of them is a compromise:

- it is **additive** — a directory of files, so there is nothing to collide with;
- it carries `paths:` front-matter, the exact analogue of Copilot's `applyTo:`, so scoping survives
  the translation rather than being flattened;
- rules without a `paths` value load at launch with the same priority as `.claude/CLAUDE.md`, which
  is the priority these instructions need.

### Why `AGENTS.md` gets a block rather than being owned

The same reasoning, applied to a file that already exists in mature repositories.
`upsert_conformance_block` has maintained a marker-delimited block in
`.github/copilot-instructions.md` since the beginning: it creates the file when absent, refreshes
what is between the markers, and **preserves everything outside them**. Generalising it to a second
destination cost one parameter.

An adopter's `AGENTS.md` therefore keeps its own content in full, and a re-install refreshes the
block without duplicating it. Both are asserted.

### The conformance block was itself false

It stated *"`.github/instructions/*.instructions.md` are mandatory. Read them before acting."* True
for one agent, false for the one reading it, and delivered only into a Copilot file. It now names
the instruction **set** and says where each agent finds it, including the canonical copy for agents
this framework has never heard of.

### Alternatives rejected

- **Emit `AGENTS.md` alone**, per `DR-12`. Inert for Claude Code without a `CLAUDE.md` importing it,
  which is the whole finding.
- **Write the adopter's `CLAUDE.md`.** Destroys content no framework can replace.
- **Symlink `CLAUDE.md` to `AGENTS.md`**, which the documentation offers. Rejected: it requires
  Administrator privileges or Developer Mode on Windows, and it silently replaces an adopter's file
  when one exists.
- **Drop the Copilot emitter** now that a working one exists. Rejected: Copilot is a real target and
  removing it would break adopters for no benefit. Its output is byte-identical to what shipped
  before, and that is asserted rather than assumed.
- **Ask each adopter to wire the instructions up themselves.** That is the status quo, and the
  status quo produced a framework that had never read its own instructions.

## Impact

- **Numerical/model output:** none.
- **Contracts/schemas:** none.
- **Security/data:** none. Nothing is read from the adopter beyond what the installer already read.
- **Operations/release:** the payload grows from 45 to 57 files — six Claude Code rules and six
  canonical copies. `AGENTS.md` joins `.github/copilot-instructions.md` as a file the installer
  maintains a block in, and `SP006`/`SP007`/`SP008` now cover both.
- **Every adopter's next upgrade** gains `.claude/rules/` and an `AGENTS.md` block. Nothing they own
  is overwritten.
- **This repository is changed most.** It acquires `AGENTS.md`, `.claude/rules/` and a `CLAUDE.md`
  it never had.

## Evidence

Eleven probes. **Three are negative controls**, and they carry the weight — an emitter that simply
overwrote agent files would pass every positive case identically.

| Probe | Result |
|---|---|
| Six rules emitted for Claude Code, six for Copilot | present |
| Both forms carry the identical body from one source | identical |
| **Copilot form still uses `applyTo`** | unchanged, and byte-identical to the previous release |
| `AGENTS.md` created where absent, carrying the block | created |
| **`CLAUDE.md` written by the installer** | **never** — the file belongs to the adopter |
| **An adopter's own `AGENTS.md` content** | **survives verbatim**, block appended |
| Their `CLAUDE.md` after install | byte-for-byte unchanged |
| Re-install | block refreshed, not duplicated |
| Block edited by hand in `AGENTS.md` | `SP008` |

`test_install_and_check.py` moves 161 → 170; `validate_contracts.py` 152 → 164.

**A defect the probes caught.** `verify_source` iterated every payload value calling `.is_file()`,
which raised the moment a payload entry became rendered text rather than a path. The first install
attempt failed outright — loudly, which is the good case.

**A fixture that had drifted.** The `no-history` fixture reconstructs an install by copying an
enumerated list of directories. It went red because that list did not know about `.claude/` or
`AGENTS.md` — an enumeration standing in for a derivation, which is `F23`'s shape in a test fixture.

## Limitations and follow-up

- **It is not established that the instructions are now read.** Files existing in documented
  locations is not content entering a context window, and that distinction *is* this finding.
  Observable in a later session via `/context` under **Memory files**; not observed yet, and not
  claimed.
- **Whether Copilot reads its form is untested.** The format is documented as Copilot's and no
  Copilot session has been run against it. Recorded rather than asserted, for the same reason.
- **Only two agents are emitted for.** Cursor, Windsurf, Cline and others have their own
  conventions. The canonical copy in `.standards/agent-instructions/` is what they get, and loading
  it is the adopter's job — stated in the conformance block rather than left to be discovered.
- **`.github/` is still 8 of 57 installed files** — the skills and the conformance workflow. Forge
  neutrality is a separate, larger question than agent neutrality, and this record does not touch
  it.
- **All six instructions remain repo-wide.** `scope: "**"` throughout, so nothing is path-scoped and
  every rule loads every session. Whether some should be narrowed is a content question, deferred.
