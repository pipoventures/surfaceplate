# Decision Record

- Decision ID: DR-78
- Date: 2026-09-09
- Application: Surfaceplate (the framework itself) — three places where the tool said something
  that was not true of what it did.
- Decision owner: Mario Pipo (maintainer), under the instruction to work through the remaining
  decisions autonomously and review at the end. Drafted by the agent under `ACT-083`; confirmed by
  merging.
- Status: accepted — implemented by `ACT-083`.
- Risk level: 2 — one change makes a previously accepted command a usage error.
- Related work item: `ACT-083`; **closes `F139`, `F140`, `F141`**; adjudicates `PW-07`, `PW-08`,
  `PW-12` out of `F136`.

## Decision

1. **`F140` — an edit needs a reason, and the rule lives with the writer.** `wizard.edit` refuses a
   blank or whitespace `because`. The CLI keeps a friendlier message and exit 3.
2. **`F139` — the renderer's `KeyError` becomes a refusal.** `--edit` against a profile it cannot
   re-render says so, and says what does work.
3. **`F141` — the installer reports the direction, not merely the difference**, using
   `rules.currency_state`; `doctor` reports a recorded version that disagrees with the digest
   instead of printing both.

## Context and alternatives

**All three are the same species**, which is why they are one record: the tool made a statement
that its own behaviour did not support. It called a downgrade an upgrade. It called boilerplate a
reason. It called an unhandled `KeyError` the end of the wizard. None is a wrong computation; each
is a wrong thing said about a right one — and this framework's entire proposition is that it does
not do that.

**`F140`: rejected — keep accepting it and improve the boilerplate.** No wording makes an absent
reason into a present one. `SP031` refuses a gate deferred without a reason on the grounds that it
is *"an omission wearing a decision's clothes"*; the same standard cannot exempt its own provenance
record.

**`F140`: rejected — enforce it in the CLI only.** That binds one caller. The invariant is about
what may be *written*, so it belongs with the writer, and every caller is bound by it. The CLI
guard stays because a usage error deserves a usage error's exit code and a kinder sentence.

**`F139`: rejected — make `--edit` work on the template.** `--edit` re-renders the whole profile
by design, which is what gives it the wizard's own validation. Making it tolerate a half-formed
file would mean a second, weaker renderer, and a profile written by neither. Refusing and naming
the two things that do work is the smaller and more honest answer.

**`F141`: rejected — refuse the downgrade.** Installing an older version deliberately is
legitimate — pinning, bisecting, reproducing an old result. What was wrong was the announcement,
not the action.

## Impact

- `surfaceplate adopt --edit` without `--because` is now an error where it used to succeed. **This
  is a breaking change to a command's accepted input**, taken deliberately before 1.0 and with no
  adopters; a script relying on the old behaviour gains a required flag.
- `install_standard` prints `a DOWNGRADE` where the recorded version is newer, with a sentence on
  what installing anyway does.
- `doctor`'s *"tool vs installed"* warns when the digest and the recorded version disagree.
- `tests/test_adopt.py` 276 → 281, `tests/test_install_and_check.py` 339 → 342.

## Evidence

- `wizard.edit(..., because="")` and `because="   "` both raise `WriteRefused`; a real reason
  proceeds to the *next* refusal, which is how the template case is reached.
- `--edit` on the installer's template profile refuses with a message naming the missing block and
  no `KeyError`; the run reports that nothing was written.
- Installing over a recorded `99.0.0` says `a DOWNGRADE`; over `0.0.1` it still says `an UPGRADE`.
  **Both directions asserted** — a check that only ever returns one answer has not been shown to
  distinguish anything.
- `doctor` against a record hand-edited to `99.0.0` warns that the files match the tool while the
  record calls them something else, instead of printing two versions and letting the reader pick.

## Limitations and follow-up

**Two existing tests now pass a reason they did not before.** They exercise *other* refusals and
would otherwise stop at this one, testing nothing they are named for. That is supplying a
now-required argument rather than weakening a test, and both carry a comment saying so — but it is
the kind of change that deserves to be visible in a record rather than only in a diff.

**`doctor`'s warning does not say which is right**, because it cannot: a digest match proves the
files are this tool's, and a recorded version is a claim about them. It names the reliable half and
points at `SP005`, which is the check that already owns the question.
