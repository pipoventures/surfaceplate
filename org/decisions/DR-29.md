# Decision Record

- Decision ID: DR-29
- Date: 2026-08-31
- Application: Surfaceplate (the framework itself) — a decision about how it is installed, and a
  correction to what one of its findings establishes.
- Decision owner: Mario Pipo (maintainer), per the decision-maker convention recorded in
  `org/decisions/README.md`.
- Status: accepted — implemented in the same change.
- Risk level: 2 — it changes what the installer will do in every adopting repository, and it changes
  what a passing `local_hook` claim means.
- Related work item: `ACT-017`. Closes `F27` and `F28`.

## Decision

**The pre-commit hook may be declined at install, and declining is recorded and announced.**

`--no-hooks` installs everything except `.githooks/`, leaves `core.hooksPath` untouched, and writes
`"hooks": "declined"` into `.standards/INSTALL.json`. Every conformance check then reports that
nothing gates staged changes and that the repository relies on `history_audit` and `review`.

**And `SP038` now asks whether the hook Git will run is the one this standard installed**, rather
than whether any hook exists.

## Context and alternatives

### The blocker

Surfaceplate could not install into Plyego at all. Plyego has a working 12,785-byte pre-commit hook
reached through a deliberate chain — a machine-wide `core.hooksPath` whose hook is delegation-only
and `exec`s the repo-local one, written precisely because *"`core.hooksPath` REPLACES `.git/hooks`
rather than adding to it… the gate reads as present because the file is still on disk, while git
never calls it."*

The installer detects this and refuses, atomically, exit 4. **That behaviour is correct and is kept
unchanged.**

### Why the refusal was nevertheless a defect

`SP038` fires only when a gate's `enforcement` list claims `local_hook`. A profile declaring
`enforcement: [history_audit, review]` has always been fully conformant with no surfaceplate hook
anywhere.

**So the standard permitted what the installer forbade.** Two parts of one framework disagreeing
about the same obligation is the defect this project names more often than any other, and it was
sitting inside the project.

The consequences were not marginal. Both offered remedies assume the adopter wants the hook; the
blocked case is any repository with existing commit-time automation, which is the target rather than
an edge case; and forty-five files were withheld over one optional 25-line shim.

### Why declining is recorded rather than silent

A bare `--no-hooks` flag was considered and rejected. It leaves no trace: nothing in the repository
or in a passing check would distinguish *"staged changes are gated before they are committed"* from
*"nothing gates them"*. That is the same shape as the hazard the machine-wide delegation hook exists
to prevent, and this register has recorded it repeatedly.

Every other narrowing in this framework announces itself — `DR-22`'s placeholder exemptions,
`SP054`'s deferral dates, `DR-27`'s *"references were not checked"* notes. A silent opt-out would
have been conspicuous by its inconsistency with all of them.

It is an **advisory and not a finding**, because declining is permitted. What would be a finding is
claiming an enforcement route you do not have, and `SP038` covers that.

### Why chaining was rejected

Teaching surfaceplate's hook to delegate onward to whatever it displaced would keep both gates and
need no opt-out. Rejected on three grounds:

- `.githooks/pre-commit` is standard-owned and integrity-checked, so delegation logic would ship to
  every adopter and have to be correct for arbitrary hooks it has never seen.
- Once `core.hooksPath=.githooks`, the displaced hook is dead to Git and reachable **only** if
  surfaceplate calls it. The framework would become the permanent owner of another system's hook.
- Remove surfaceplate later and the adopter's hook silently stops running again — the original
  hazard, reintroduced by the remedy.

The adopter-side equivalent is better and costs the framework nothing: a repository's own hook can
call `.standards/check_conformance.py --repo . --staged` in three lines. That is Plyego's work, in a
file Plyego owns, and it is the right ownership boundary.

### `F28`, found by the probe rather than by reading

The approved plan for this packet asserted that *"`SP038` is untouched and still catches a gate
claiming a hook that was declined."* **That was false when written.**

`active_pre_commit_hook` asked only whether an executable `pre-commit` existed in the active hooks
directory. Any hook satisfied it. So a gate could claim `local_hook` and be satisfied by a hook that
formats code or prints a message — and the finding's silence established *"a hook exists"* rather
than *"the conformance check runs before commit"*.

It predates this work and was exposed by it: declining leaves `core.hooksPath` pointing at the
adopter's own hook, which passed the old test perfectly. The probe written to demonstrate the
guarantee found there was none.

The remedy needed no new data. `.standards/INSTALL.json` has always carried the digest of
`.githooks/pre-commit`, so the active hook is compared against the one the standard installed. A
record with no such entry — because hooks were declined — cannot support the claim, which is the
right answer rather than a special case.

Three failure modes are now distinguished, and each is asserted: no hook at all; a hook that is not
this standard's; hooks declined at install. `SP038`'s title changed with them, because *"there is no
hook"* is plainly wrong against a repository that has one.

**Fixing this was inside the packet's promise, not scope added to it.** The plan asserted the
guarantee; the guarantee did not exist.

### Alternatives rejected

- **Bare `--no-hooks`.** Above.
- **Chaining in the framework.** Above.
- **Leave it, and have adopters neutralise their git configuration during install** — which is what
  the Plyego probe did. Rejected: it is a workaround that only works for someone who already knows
  the internals, and it leaves the contradiction standing for everyone else.
- **Make the hook mandatory in the standard too**, resolving the contradiction the other way.
  Rejected: `history_audit` genuinely enforces these gates against real commits, and a repository
  auditing its history is not less governed than one running a hook. It would also make the
  framework uninstallable in exactly the repositories most likely to want it.

## Impact

- **Numerical/model output:** none.
- **Contracts/schemas:** none. `INSTALL.json` gains an optional key; absent means installed, so every
  record written before 0.17.0 reads correctly with no migration.
- **Security/data:** none. `framework_digest` is `sha256(MANIFEST.sha256)` over the *source*, so a
  partial install still pins the version it came from and `SP048`/`SP049` keep working.
- **Operations/release:** repositories with their own hook systems can adopt. Existing installs are
  unaffected.
- **`SP038` gets stricter for everyone.** An adopter whose `local_hook` claim was satisfied by an
  unrelated hook now sees a finding. It is graceable, and it is correct: the claim was false.

## Evidence

Nine probes. **Three are negative controls**, and they carry the weight — an opt-out that quietly
disabled conflict detection for every install would pass the positive cases identically.

| Probe | Result |
|---|---|
| Default install, foreign `core.hooksPath` | `STOPPED`, exit 4, **nothing written** |
| …and the refusal names the third route | `--no-hooks` present in the message |
| `--no-hooks` into the same repository | installs; `core.hooksPath` unchanged; no `.githooks/` in the tree or the record |
| …declination recorded | `"hooks": "declined"`, `executable_files: []` |
| …check passes and says so | `PASS` + advisory |
| Claiming `local_hook` after declining | `SP038`, **though an executable hook is present** |
| An unrelated hook, `local_hook` claimed | `SP038` — *"is not the hook this standard installed"* |
| Default install, clean repository | hook installed, `core.hooksPath=.githooks`, **no** advisory |
| The standard's own hook active, `local_hook` claimed | silent — the claim is honoured |

`test_install_and_check.py` moves 154 → 161.

**A slip the probes caught, recorded because reading the code would not have found it.** The first
implementation filtered only `.githooks/pre-commit` from the payload. `.githooks/` also carries a
`.gitattributes`, so declining left an orphan directory holding one file governing a hook that was
not there.

## Limitations and follow-up

- **`--no-hooks` is a real reduction in enforcement**, not a formality. Gates fall back to
  `history_audit` and `review`, which catch a violation after it is committed rather than before.
  The advisory says this in those terms.
- **Nothing verifies that the adopter's own hook does anything useful.** The framework's position is
  that it is not surfaceplate's hook and not surfaceplate's business; what changed is that it can no
  longer be mistaken for one.
- **`SP038` still cannot establish that the standard's hook will actually run** — only that the file
  Git resolves is the one installed. A hooks directory made unreadable between check and commit, or
  a `--no-verify` commit, defeat it. `--no-verify` in particular is why `history_audit` exists.
- **Plyego still has no commit-time conformance check** after adopting with `--no-hooks`. The remedy
  is three lines in `scripts/install_hooks.sh`, on Plyego's side, and is not done here.
