## Decision

1. The gate list opens with the level's floor expanded and nothing else: the gates the level
   requires, plus the interface gates where the repository has a user interface. Every other gate
   sits folded under one heading that names the level and the count - "Beyond the standard
   floor: 15 gates, not required" - and one key opens it.
2. Nothing is hidden and nothing is decided on the adopter's behalf. A folded gate is still a
   gate to decide: the bulk command (`DR-47` (4)) still declares every undecided gate not
   applicable in one recorded act, and opening the fold shows each as before.
3. The counter names the floor: how many the level requires, how many lie beyond it, how many
   are undecided, how many complete.
4. The above-floor list on the remainder form says how many controls the level already
   requires, so the level's effect is visible there too.

## Context and alternatives

`F91`, the maintainer's words: *"haven't seen much difference between standard and full. ... If
we leave all the ones selected as optional the conformance level tells us nothing."* At
`standard` and `full` alike the list showed all nineteen gates with the floor merely locked.
Alternatives put and not chosen: the floor only, with the rest as a separate opt-in list (fewer
rows, one more screen); every gate listed with the floor ordered first (the smallest change and
the weakest signal).
