# Decision Record

- Decision ID: DR-17
- Date: 2026-08-31
- Application: Surfaceplate (the framework itself) — a decision about a published control, not
  about an adopting application.
- Decision owner: Mario Pipo (maintainer), per the decision-maker convention recorded in
  `org/decisions/README.md`.
- Status: accepted — implemented in the same change.
- Risk level: 2 — "output-affecting code, data, schema, or workflow", per the risk table in
  `core/REVIEW_AND_EVIDENCE.md`. It changes when `SP032` fires, which changes the pass/fail
  result of the conformance check in every adopting repository.
- Related work item: `ACT-004`, registered in `activity/register.md`. Raised by `F14`.

## Decision

**Remove the shape-based branch from `PLACEHOLDER_PATTERN` in `scripts/check_conformance.py`,
and close the false negative that removing it exposed.**

Concretely, four changes that must land together:

1. `PLACEHOLDER_PATTERN` drops `<[a-z0-9_\- ]{1,30}>`. Detection is now by token only:
   `replace-me`, `TODO`, `TBD`, `TBC`.
2. `templates/decision-record.md` and `templates/work-packet.md` gain a visible `replace-me`
   marker, because they carried no marker of any kind and were undetectable.
3. `tests/validate_contracts.py` gains two guards: every file under `templates/` must be
   detectable as a template, and the pattern must **not** match three notation strings taken
   from this repository's own documents.
4. `tests/test_install_and_check.py` pins both directions of `SP032` end to end.

`core/PREREQUISITE_GATES.md` is updated in the same change, because it is the document that
governs this behaviour and it previously described a detection rule that no longer holds.

## Context and alternatives

### Why the branch was there, and why it cannot work

The branch encoded a reasonable theory: an unfilled template slot looks like `<your-org>`. The
author was already aware it could misfire — the character class excludes `@` and `.` so that an
email address in angle brackets would not trip it, and the comment said so.

The theory fails because the distinction it requires is not available at the level it operates.
`<your-org>` and `<schema-file-name>` are the same string shape. Nothing lexical separates a slot
awaiting a value from a metavariable naming a class of values. A check cannot draw a distinction
its input does not carry.

### The measurement

`F14` records it in full. Against this repository: **seven matches across six files, zero of
them placeholders.** Two numbering conventions (`DR-<n>`, `F<n>`), a command template inside
`core/PREREQUISITE_GATES.md` itself (`git log --since=<effective_from>`), a CLI usage line in
`scripts/verify_release.py`, and a historical URN form in `CHANGELOG.md`.

Three of the six files are normative documents this framework publishes. The defect was
therefore never publisher-specific: any adopter whose governed artefact contained a usage line
got a spurious `SP032` on a gate that is a **floor at `standard`** — a control failing on
correct work, which `core/CONTROL_PRINCIPLES.md` treats as worse than no control, because it
teaches the reader to ignore the output.

### What removing it costs — measured, not assumed

Nothing detectable is lost. `templates/application-profile.yaml` is the only template that
carried an angle-bracket slot (`<application-id>`, `<control>`), and it also carries
`replace-me`, so file-level detection is unchanged. No test depended on the branch: the existing
contract test at `tests/test_install_and_check.py` uses `owner: replace-me`.

### The false negative the audit exposed

Checking what the branch was worth required enumerating what the framework's own templates
actually contain, and that turned up a separate defect the branch had been masking the absence
of. `templates/decision-record.md` and `templates/work-packet.md` mark their blanks with **a key
and an empty value** — `- Decision ID:` — which matches neither branch. Two of five shipped
templates were undetectable. A gate naming either as its precondition artefact would have passed
`SP032` while pointing at a blank form: precisely the condition `SP032` exists to catch.

Fixing this by teaching the checker to detect empty-value-after-colon was rejected. It is a
second shape-based heuristic of exactly the kind being removed, and it would misfire on ordinary
prose (`## Impact` sections, list items continued on the next line). The fix belongs in the
templates, where the convention is chosen, not in the checker, where it must be guessed.

### Alternatives considered and rejected

- **Narrow the branch to ignore Markdown code spans.** Clears four of the five gate-relevant
  occurrences but not the `.py` usage line, and puts Markdown parsing inside a general-purpose
  check. A partial fix with new failure modes.
- **Compare each artefact against the template it was copied from.** Precise, but most
  precondition artefacts — a changelog, a register, a design policy — have no template to
  compare against. It answers a narrower question than the control asks.
- **Leave it and edit the offending documents.** Rejected: it would mean rewriting a historical
  `CHANGELOG` entry and a normative document to satisfy a check that is wrong, and would leave
  every adopter with the same failure.
- **Leave it and accept `WARN`.** The findings are graceable, so this repository could have
  landed self-conformance at `WARN` with grace expiring 2026-09-30. Rejected by the maintainer
  on the grounds that self-conformance established through an instrument known to be wrong is
  not worth establishing. That is the reasoning this record exists to preserve.

### Why this is a separate record and a separate activity

`F14` was found by the work that was trying to make this repository pass the check. Changing a
published control's behaviour inside that work would have been indistinguishable — in the diff,
to a reviewer later — from adjusting the control to obtain a pass, however sound the reasoning.
`ACT-004` was registered with **no dependency on `ACT-001`** so that this change stands or falls
on its own evidence. The discriminating question was asked explicitly: *would this change be
made if it did not help the publisher pass?* It would — an adopter hitting the same false
failure would warrant the same fix.

That separation is a claim about intent, and intent is not verifiable. The guards in §Evidence
are what make it checkable instead.

## Impact

- **Numerical/model output:** none. The framework produces no numerical output.
- **Contracts/schemas:** unchanged. No schema, no `SP0xx` code added or removed. `SP032` keeps
  its identifier, its message and its graceability; only the condition that triggers it narrows.
- **Security/data:** none.
- **Reproducibility/lineage:** the vendored copy under `.standards/` is reinstalled in the same
  change, so the two copies do not diverge at landing. This is `F12`'s hazard and it is handled
  here by reinstalling, not by ignoring it.
- **Operations/release:** an adopting repository that was failing `SP032` on notation will now
  pass. An adopting repository relying on angle brackets to mark its own blanks will now pass
  where it previously failed — stated as a real reduction in coverage, and documented in
  `core/PREREQUISITE_GATES.md` so adopters can act on it rather than discover it.

## Evidence

- **The measurement**: seven occurrences, six files, zero true positives — tabulated in `F14`.
- **Both directions pinned, and both seen to fail.** Asserting a test passes is not evidence it
  can fail; each guard was made to fail deliberately before being trusted:
  - Reinstating the removed branch in a scratch copy fails `validate_contracts.py` with
    *"PLACEHOLDER_PATTERN matches notation, not a placeholder: 'Records are numbered `DR-<n>`…'"*.
  - Stripping the marker from `templates/work-packet.md` in a scratch copy fails with
    *"templates/work-packet.md is not detectable as a template."*
  - `test_install_and_check.py` reports five new `PASS` lines: `replace-me`, `TODO`, `TBD` and
    `TBC` each rejected, and angle-bracket notation **not** rejected.
- **Suite counts**: `validate_contracts.py` 82 → 90; `test_install_and_check.py` 97 → 101. The
  increase is accounted for: five templates plus three notation strings, and four new `SP032`
  cases.

## Limitations and follow-up

- **Coverage genuinely narrowed.** An artefact marking blanks by any convention other than the
  four tokens is undetected. This is not fully remedied — it is bounded (every shipped template
  now carries a marker) and documented. The general problem, detecting an unfinished document,
  is not solved and is not claimed to be.
- **The guard protects the pattern, not the idea.** `validate_contracts.py` prevents the
  branch being reinstated silently and prevents a shipped template losing its marker. Neither
  guard would notice a *new* placeholder convention being introduced somewhere else.
- **The token branch has the same defect, narrowed — do not read this record as claiming it
  sound.** `F16`, found while landing this change: the `CHANGELOG.md` entry documenting this
  decision spelled out the four tokens, and `CHANGELOG.md` is a precondition artefact, so the
  entry describing the fix failed the check it described. Whole-file matching cannot separate
  mentioning a token from containing an unfilled slot, and no token vocabulary avoids that. Four
  fixed strings is a far smaller surface than any angle-bracketed string, which is why this
  record still holds — but the argument for removing the shape-based branch was *"it cannot draw
  a distinction its input does not carry"*, and that argument applies here too, in degree rather
  than in kind. The convention adopted — `core/PREREQUISITE_GATES.md` is the only document that
  spells the tokens out — is a writing habit, not a control, and does nothing for adopters.
- **`F15` records the false negative** as a finding in its own right, closed by this change for
  the templates this framework ships and open in general.
