# Decision Record

- Decision ID: DR-43
- Date: 2026-09-01
- Application: Surfaceplate (the framework itself) — what `surfaceplate adopt` may write into an
  adopting repository.
- Decision owner: Mario Pipo (maintainer), per the decision-maker convention recorded in
  `org/decisions/README.md`.
- Status: accepted — implemented in the same change (`ACT-033`).
- Risk level: 4 — it makes this tool write files into someone else's repository for the first time,
  and the artefacts it writes are the ones a published control checks for.
- Related work item: `ACT-033`. Raises `F47`.

## Decision

**Where a required gate has no artefact, offer to create a real one. Show it, never overwrite, write
nothing without approval, and say plainly what creating it does not do.**

1. **Seeds, not templates.** A new `surfaceplate/seeds/` holding four complete, placeholder-free
   documents — valid the moment they are written.
2. **Four artefacts, covering `essential` and `standard` completely.** The seven further gates
   `full` requires are not seeded, because nothing true could be created for them.
3. **Never replace.** An existing path is not offered at all, and `write()` refuses again at the
   point of writing.
4. **The honesty is at the point of use** — in the seed's own text, on the offer screen, and in the
   run's closing report.

## Context and alternatives

### Why the obvious design is wrong, and how that was established

The intuitive implementation is to copy `surfaceplate/templates/decision-record.md` into place.
**It would have produced a gate artefact that fails the checker on the very next run.** Every
shipped template deliberately carries placeholder tokens — `F15` made them do so, precisely so an
unfilled template is caught — and `SP032` rejects a precondition artefact containing one:

| template | placeholder tokens |
|---|---|
| `application-profile.yaml` | 18 |
| `override-record.yaml` | 14 |
| `gate-exception.yaml` | 7 |
| `decision-record.md`, `work-packet.md` | 1 each |

That is the whole reason `seeds/` is a separate idea from `templates/`. A template announces that it
is not finished; a seed is finished and holds no entries. `tests/test_scaffold.py` asserts the
distinction against `check_conformance` itself rather than against a copy of its token list, because
a token list is a belief about the checker and the checker is what decides.

### The risk this carries rather than solves

**Creating a register does not register anything.** The gate's structural check — artefact exists,
non-empty, no placeholder — passes on the file being there. The practice it stands for may never
happen, and the checker cannot tell the difference.

That is `F40`'s shape, and the reason this is a decision record and not a feature note. What makes
it defensible rather than a dressed-up false green:

- **A register is the right kind of object.** The practice can attach to it and grow inside it. A
  README, which is what `F40` proposed, can never become one — pointing the gate there meant the
  gate could never be about registration at all.
- **The labelling is at the point of use**, which is what `surfaceplate-provenance.md` requires and
  what a single global disclaimer does not satisfy. The seed's own opening paragraph says its
  existence is not the practice and that an empty register with work happening around it is a
  finding; the offer screen says it while the adopter is choosing; the closing report says it beside
  the paths written.
- **Only what can be created truthfully is created.** `full` requires eleven gates and four are
  seeded. An equivalence-evidence protocol or an output-validation record cannot be written empty
  and remain a true statement about a repository, so those are left to a human who has one. Where
  nothing honest can be created the wizard says nothing matches, exactly as `ACT-034` made it.

### `F47`, found by writing the test that was supposed to prove this worked

The packet's headline assertion was that a bare repository could adopt and then pass. It cannot, and
the finding is what stopped that from being written as though it could.

The artefact is created today; `effective_from` is today; the audit asks of every commit since that
date whether the artefact existed, and commits made **earlier the same day** were made when it did
not. The natural remedy — bind the gate from tomorrow, which is what the artefact's real history
justifies — was tried and **the checker refused it**, correctly: `SP033` rejects a gate dated in the
future.

Three candidate remedies, none chosen here because each changes a published control's meaning:
compare commit timestamps rather than dates; treat the commit introducing an artefact as the
boundary; or let `effective_from` carry a time. That is its own packet with its own decision, not a
side effect of adding scaffolding.

**What was done instead is the part worth keeping:** the test asserts the true outcome — the
artefact exists, the gate names it, and the only outstanding finding is `SP035` over pre-adoption
history. Asserting a clean check would have *passed*, because `check_conformance.main` returns 0
inside the adoption grace window whether or not anything is outstanding. A green test resting on a
grace period is exactly the false green this project exists to find.

### On the adversarial review

An adversarial review of the scaffold path was run by a **Fable** subagent before merge, and its
findings are reflected in the code. **This is not `RELEASE_PLAN` item 9 and does not advance it.**
Item 9 specifies a *cross-provider* review deliberately: two Claude models share training lineage
and therefore blind spots, so this is a cheap second reading, not a second instrument in the sense
that record means. Item 9 remains next in the declared order.

### Alternatives rejected

- **Write the artefacts silently on adoption.** Fastest path to a passing check and the one thing
  this package must not do: creating files in someone's repository without showing them is the
  behaviour it tells adopters to review other tools for.
- **Copy the shipped templates.** Fails `SP032` immediately, as measured above.
- **Seed all eleven `full` gates.** Would require inventing evidence documents that assert
  validation which has not happened.
- **Ship the seeds into `.standards/`.** They are materials this tool draws from, not files the
  standard owns and integrity-checks in someone else's repository; installing them would grow every
  adopter's payload for no benefit, since the wizard always runs from the package.

## Impact

- **Numerical/model output:** none.
- **Contracts/schemas:** none. The profile is unchanged in shape; `wizard.run` now returns a
  `Written` carrying the profile path and any created paths, delegating everything else to the path
  so existing callers are unaffected.
- **Security/dependencies:** this tool now writes files outside `governance/` in an adopting
  repository. Bounded by: four fixed relative paths, refusal on any existing path checked twice, and
  no write before human approval.
- **Operations/release:** an adopter with an empty repository can complete adoption with a gate that
  names something real, instead of leaving it blank or naming the closest wrong file.

## Evidence

- Eleven suites pass: contracts 167, installer 183, adopt 82, provenance 6, adopt-tui 41, render 18,
  discover 18, scaffold 14, identifiers 185, registers 10 (47 F codes).
- **The provenance allow-list did not grow.** Seeds are separate files, not profile values; the only
  thing entering the profile is a path a human accepted. That was this packet's stated condition.
- **Seen to fail:** adding `TODO:` to a seed makes the suite report
  *"these would fail SP032 the moment they were written: [CHANGELOG.md]"*.
- **Never-overwrite asserted in both directions**, including an offer built before a file existed
  being unable to replace it, and a whole-tree hash proving that declining writes nothing anywhere.
- The `Written` wrapper's first form enumerated the path methods it thought callers used, and broke
  `test_adopt` on `.is_file`. Delegating everything undefined was the fix; the first attempt is
  recorded because guessing an interface's surface is what failed, not the idea.

## Limitations and follow-up

- **`F47` is open**, and it is the difference between "has a real artefact" and "passes cleanly".
- **The seeds are prose written by this project**, and their quality is a judgement. They are short
  by intent: a long seed is a document nobody reads and a lie about how much work adoption did.
- **Four artefacts, not eleven.** `full`-level adopters still meet seven gates with nothing offered.
- **Nobody has yet accepted the offer in a real run.** Every previous round of this wizard was
  corrected by one, and there is no reason to expect this to differ.
- **The adversarial review was same-provider**, and is recorded above as not advancing item 9.
