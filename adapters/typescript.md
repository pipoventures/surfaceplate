# TypeScript/React Adapter

Recommended native implementation: TypeScript domain/API types generated from or checked against canonical backend schemas; ESLint and formatter; `tsc --noEmit`; deterministic frontend tests; production build; explicit loading, empty, error, and stale-data states.

Treat the frontend as a client of stable contracts. Do not place quantitative/model methodology in components. Display provenance, run status, warnings, overrides, and human-review state from API data. Keep visual conventions application-specific rather than importing PEM/Shiny UI patterns.
